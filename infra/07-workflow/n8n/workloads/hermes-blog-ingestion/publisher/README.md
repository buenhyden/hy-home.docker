# Hermes 로컬 발행기

## Overview

완료된 구조화 결과와 연결된 원본을 제한적으로 읽고 영속 대기함에 보존합니다.
Blog-data `dev`의 고정 계약을 사용하는 어댑터와 합성 시험을 준비했지만 실제
Gateway와 연결하지 않았습니다. 초기 보존 상태는 `awaiting_contract`입니다.
실제 기사 수집 시각의 근거와 운영 전송 연결이 없어 전송할 수 없습니다.
`collected_at`은 보고서에 포함된 모든 항목의 실제 수집 시각 중 가장 늦은 시각입니다.
항목 하나라도 근거가 없으면 보고서 전체를 보류하며 현재 후보에는 그 근거가 없습니다.
Hermes 후보의 `generated_at`이 소수점 6자리인 경우 후보 원문은 그대로 보존합니다.
Gateway 계약에 맞춘 전송 값은 밀리초 단위로 내리므로 최대 999마이크로초가
손실되고, Gateway에는 소수점 이하 3자리만 전달됩니다. 단건 전송 CLI를
합성으로 검토했으나 실제 기사 수집 시각 provenance와 relay 목적지 결속을
증명하지 못해 제거했습니다. 이후 추가된 `dispatch`는 기존 전송 처리기·어댑터·
재전송 경계·HTTP 전송기를 그대로 연결합니다. 세 Hermes 작업의 차단 정책이 닫혀
있는 동안 인증 파일을 읽거나 네트워크 요청을 보내기 전에 `blocked`를 반환합니다.
준비된 요청은 계약 개정·논리 목적지·본문과 함께 전송기가 제공한 relay endpoint
문자열의 SHA-256도 대기함에 고정합니다. 이후 전송 또는 재전송에서 어느 하나라도
달라지면 실패하며 다른 endpoint로 조용히 전송하지 않습니다.

## Scope

호출자가 선택한 검증기의 정확한 다이제스트와
`validate(data)`로 구조를 확인합니다. Publisher는 별도로 디렉터리 기준의
no-follow 읽기와 제한된 기준 경로·SHA-256을 검사합니다. 검증기는 아직 게시되지
않은 SPEC0247 브랜치 초안(`8c988c71…`)에서 main에 추적되는
`scripts/validation/check-hermes-candidate.py`(`957d047c…`, 커밋 `1003fbe8a`)로
고정을 옮겼습니다. 초안 다이제스트는 거부하며 소스를 복사하거나 수정하지 않습니다.
검증기 바이트가 바뀌면 시험이 실패하므로 독립 검토 뒤 이 상수를 함께 갱신합니다.
승인된 세 작업의 원본 및 아이디어 참조만 읽고,
심볼릭 링크·경로 이탈·해시 불일치·미완료·비공개 입력을 거부합니다.
여기서 선택하는 기준 경로는 홈 전체에 대한 접근이나 연결 권한을 뜻하지 않습니다.

## Structure

- [cli.py](cli.py): 파일 준비·집계 상태·제한된 전송 명령입니다.
- [evidence.py](evidence.py): Hermes Companion Evidence v1의 구조·결속 검증입니다.
  생산자 인증이 아니며 전송 권한을 만들지 않습니다.
- [candidates.py](candidates.py): 승인된 작업과 검증기 연결입니다.
- [files.py](files.py): 제한된 파일 읽기입니다.
- [policy.py](policy.py): 세 Hermes 작업이 생산자 인증 증거를 요구한다고 선언합니다.
- [trust.py](trust.py): Ed25519 분리 서명과 추적 키 저장소로 생산자를 인증하고,
  모든 전송 경계가 함께 쓰는 단일 신뢰 판정을 반환합니다.
- [outbox.py](outbox.py): 원본 스냅숏·중복·충돌·전송 상태 보존입니다.
- [delivery.py](delivery.py): 실제 통신과 분리된 전송·대조 상태 처리입니다.
- [http_transport.py](http_transport.py): 제한된 일반 HTTP 전송과 보수적인 결과 분류입니다.
- [gateway_adapter.py](gateway_adapter.py): 고정 계약의 요청과 영속 수신 증거를 해석합니다.
- [gateway_transport.py](gateway_transport.py): 조건을 확인한 동일 요청 재전송을 선택적으로 연결합니다.
- [\_\_init\_\_.py](__init__.py): 패키지 진입점입니다.

## Usage

워크로드 디렉터리에서 아래 도움말로 인자를 확인합니다. 도움말은 원본을 읽거나
대기함을 생성하지 않습니다.

```bash
python3 -m publisher.cli --help
python3 -m publisher.cli stage --help
python3 -m publisher.cli status --help
python3 -m publisher.cli dispatch --help
```

운영 실행은 작업 사본이 아니라 보호 설치 release의 venv에서 전용 계정으로
`<release>/venv/bin/python -I -m publisher.cli <명령>`처럼 합니다.
`verify-install`은 런타임 보호와 키 저장소 해석만 확인하고 키 개수를 출력합니다.

`stage`에는 내보내기·원본·아이디어 기준 경로, 검토된 검증기 경로와 다이제스트,
전용 대기함 경로를 모두 지정합니다. 실제 대상은 연결된 운영 절차에서
확인합니다. 대기함은 저장소 밖의 전용 경로에 두며 디렉터리는 0700,
파일은 0600이어야 합니다. 바로 위 디렉터리는 먼저 존재해야 합니다.
선택적 `--evidence-root`는 Companion 원본 바이트와, 있으면 같은 이름에 `.sig`를
붙인 분리 서명을 후보·원본 스냅샷에 함께 고정합니다. 파일명은
`SHA256(job_id + NUL + run_id).json`이며 지정 시 Companion 누락, 안전하지 않은
경로, 기존 증거·서명과의 충돌은 거부합니다. 한 번 고정한 서명은 바꿀 수 없으므로
생산자는 서명을 먼저 쓰고 Companion을 나중에 게시합니다. 보존 자체는 인증이
아니며, 전송 여부는 [trust.py](trust.py)의 판정이 정합니다. 추적 키 저장소가
비어 있는 현재는 세 작업 모두 `blocked`입니다.
`status`도 대기함을 열면서 DB 생성·초기화·마이그레이션 또는 SQLite 저널
복구를 수행할 수 있으므로 읽기 전용 명령이 아닙니다. `status`는 전송 상태를
대조하거나 `sending`을 바꾸지 않습니다. 중단된 전송의 `uncertain` 전환은
전송 처리기 `process_one`이 잠금을 얻은 뒤 수행합니다.

출력은 `staged`, `duplicate`, `conflict`, `rejected` 집계 또는 상태별 건수이며
원본·인증 정보를 출력하지 않습니다. 거부나 충돌이 있으면 종료 코드 1입니다.
증거 경로를 지정한 경우 `evidence_stored` 집계도 반환합니다.
작업별 후보 파일은 최대 1,000개이며 초과 시 명시적으로 실패합니다.
파일별 8 MiB, 한 후보의 합계 32 MiB로 읽기를 제한합니다.
일괄 처리는 후보별로 보존하므로 뒤의 실패가 앞의 성공을 취소하지 않습니다.

`dispatch`는 대기함, 고정 relay endpoint, `이름: 값` 한 줄의 인증 헤더 파일을
받습니다. 인증 파일은 실행 계정 소유이고 그룹·기타 권한이 없어야 하며 인자·
환경 변수·출력에 값을 남기지 않습니다. 열린 기록마다 한 번만 처리합니다.

1. 서명·키·Companion 구조를 함께 확인하는 신뢰 판정이 실패하면 인증 파일을
   읽지 않고 `blocked`입니다. 같은 판정을 요청 결속·전송·재전송 경계도 다시
   확인하므로 그 사이 키가 폐기되면 이후 단계도 막힙니다.
2. 신뢰 판정이 돌려준 `scheduled_at`과 항목별 실제 수집 시각의 최댓값인 `collected_at`,
   후보의 `generated_at`으로 고정 계약 요청을 만들고 대기함에 결속합니다.
   HTTP 시간 제한은 45초입니다.
3. 기존 `process_one`이 한 번의 전송 또는 대조만 수행합니다. 연결 전 실패처럼
   미전송이 증명된 경우만 지수 대기 후 다음 호출에서 다시 보냅니다. 401·403·409
   등 영구 오류는 `failed`로 멈춥니다. 5xx·응답 유실·중단은 `uncertain`이며
   `--allow-replay`를 명시해야만 같은 요청 바이트로 대조합니다. 대조 없이 실행해도
   시도 횟수가 소모되며 한도(5회)를 넘으면 운영자 판단 전까지 `uncertain`으로
   남습니다. 대조 중 영구 오류를 받으면 즉시 한도를 소진해 다시 보내지 않습니다.

재시도 주기는 이 명령을 다시 실행하는 호출자가 정하며 n8n은 재시도하지
않습니다. 출력은 상태별 건수와 거부 이유 코드별 `reasons`이고 `failed`나
`uncertain`이 있으면 종료 코드 1입니다. 설정·인증 오류는 `operation_rejected`로 전체 실행을 거부합니다.

## Verification

같은 실행과 내용은 중복으로 처리하고 다른 내용은 최초 보존본과 충돌 증거를
유지합니다. 전송 본문·계약 개정·목적지의 결합은 재시작 후에도 유지합니다.
전송 중 종료된 상태는 미확정으로 옮기고 대조 없이 자동 재전송하지 않습니다.
계약 어댑터와 선택적 재전송은 고정된 합성 계약·응답으로 검증했습니다.
일반 HTTP 전송기의 기본 대조는 미확정으로 끝나며, 자동 실행 서비스나 예약
실행은 없습니다. 현재 일반 HTTP 전송기 구현은 평문 HTTP를
격리 loopback 시험에만 제한합니다. 이는 이후 승인될 내부 전송 토폴로지를
결정하지 않습니다. `uncertain` 상태는 실제 relay/Gateway 결속과 명시적인
idempotent replay 허용을 검증하기
전에는 다시 POST하지 않습니다. 실제 기사 수집 시각의 원천 근거, 인증·TLS,
n8n Queue 및 Gateway 영속 수신은 모두 운영 검증 대기입니다.
endpoint SHA-256은 구성 문자열의 불변 결속일 뿐 DNS/TLS 경로나 Blog-data tenant
소유권을 증명하지 않습니다. 승인된 운영 검증에서 인증서·자격 증명 범위·tenant
대상·영속 수신 증거를 확인해야 합니다. 기존 대기함을 처음 열 때 SQLite 열 추가
마이그레이션이 수행될 수 있습니다. Publisher는 스키마 확인과 마이그레이션을 하나의
SQLite 트랜잭션으로 직렬화하며, 동시에 여는 두 호출의 합성 시험도 통과했습니다.
운영 절차는 이 안전한 재시도 특성을 확인해야 하지만, 이 변경으로 실행 중인
Publisher·Cron·워크플로·Compose·네트워크·Credential은 바뀌지 않습니다. 실제 기사
수집 시각이 없는 항목(2026-10-31 관찰 193개)은 `collected_at`을 대체하지 않고 보류하며 전송
대상에 결속하지 않습니다. Hermes의 현재 도구 결과 메시지는 도구 반환 뒤 기록되고
여러 항목의 배치에 공유될 수 있습니다. 캐시 적중도 그 메시지만으로 새 네트워크
수집을 증명할 수 없습니다. 생산자는 Cron `run_id`와 URL·내용 다이제스트에 결속된
항목별 실제 원문 수집 시각, 시간대, 실제 수집/캐시 구분을 영속 기록해야 합니다.
배치 응답이나 결과 생성 시각은 개별 원문 수집 시각의 증거가 아니며 캐시 적중은
원래 수집의 검증 가능한 근거가 있어야 합니다. Publisher는
모든 포함 항목에 그 근거가 있을 때만 최댓값을 보고서 `collected_at`으로 계산합니다.
자식 프로세스 시작 후 DNS부터 응답 본문까지 시간 제한을 적용하며 시간 초과 시
자식을 종료하고 결과를 미확정으로 보존합니다. 프로세스 생성과 호출자의 비밀
확보 시간은 이 제한 밖입니다. 최종 합성 localhost HTTP/TLS 시험은 11건 모두
통과했고 고정 검증기 대상 시험은 14건 통과했습니다. 동시 기존 Outbox
마이그레이션 시험을 포함한 focused 합성 시험은 117건 중 115건 통과했고 2건은
선택적 skip입니다. 측정 커버리지 93%에는
자식 프로세스가 포함되지 않습니다. 사설 CA, 실제 서버 통신과 n8n Queue를 경유한
Gateway 전달은 검증되지 않았습니다. PR #695 병합 시점의 전체 합성 시험은
151건이었습니다. 생산자 인증을 추가한 현재 소스의 수치는 `SPEC-0204-TSK-0022`의
최신 기록을 따르며, 운영 n8n·Gateway 전달과 Windows 수신은 포함하지 않습니다.
