# AI Infrastructure Tier (08-ai) Product Requirements

## Overview

### Overview

### Problem and Goals

This document defines the product requirements for the `08-ai` tier. The goal is to provide a privacy-hardened, self-hosted AI service environment through a local LLM inference engine (`Ollama`) and a RAG interface (`Open WebUI`).

### Problem Statement

- High cost and data leak concerns from using cloud LLMs.
- Lack of a way to generate customized AI answers integrated with internal documents and a knowledge base.
- No centralized management or efficient allocation scheme for GPU resources.

## Requirements

### Requirements

### Functional Requirements

- **REQ-0009-FR-0001**: Support hardware-accelerated (GPU) inference via the NVIDIA Container Toolkit.
- **REQ-0009-FR-0002**: Serve and manage various open-source models (Llama3, Mistral, Qwen, and so on) via Ollama.
- **REQ-0009-FR-0003**: Provide a user-friendly chat browser interface via Open WebUI.
- **REQ-0009-FR-0004**: Support a RAG pipeline and embedding model for internal document search.
- **REQ-0009-FR-0005**: Support multi-user access and Keycloak-based SSO integration.

### Non-functional Requirements

No separately numbered non-functional requirement was identified in the source package.

### Interface Requirements

No separately numbered solution-independent external interface requirement was identified in the source package.

## Acceptance Criteria

- **REQ-0009-FR-0001**: Local model inference latency (TTFT) is under 1 second (Llama-3-8B baseline).
- **REQ-0009-FR-0002**: All data (prompts, documents) is processed within the internal network without leaking to an external network.

## Scope

### Scope

### Stakeholders and User Needs

Build a local intelligent assistant and RAG system that minimizes external cloud dependency and safely processes confidential data by efficiently using the GPU resources of the internal infrastructure.

### Personas

- **AI Engineer**: The administrator responsible for model deployment, quantization optimization, and RAG pipeline performance tuning.
- **Internal User**: A team member who uses the chat interface for everyday task assistance, document summarization, and coding support.
- **System Agent**: An agent that performs intelligent tasks within automated workflows via a dedicated API.

### Key Use Cases

- **STORY-01**: A user can converse with a locally hosted Ollama model through Open WebUI and get an answer.
- **STORY-02**: A user can upload documents to store them in a local vector DB (Qdrant) and reflect RAG search results based on them in an answer.
- **STORY-03**: An agent can call the Ollama API to perform structured data extraction or text analysis tasks.

### Constraints

- **In Scope**:
  - LLM inference engine (Ollama) configuration and GPU integration.
  - RAG orchestration (Open WebUI) and UI provision.
  - Model persistent storage and permission management.
- **Out of Scope**:
  - Fine-tuning or pretraining (training) of large-scale models.
  - Providing a high-performance LLM API for external services (internal focus only).

### AI Agent Requirements

- **Allowed Actions**: Query the model list, generate chat, generate embeddings, upload documents.
- **Disallowed Actions**: Modify physical files on the host system, send confidential prompts to the external internet.
- **Evaluation Expectation**: Answer faithfulness and answer relevance against search results.

### Risks

- **Risks**: OOM (out of memory) and service interruption due to insufficient GPU VRAM.
- **Dependencies**: NVIDIA GPU driver and Container Toolkit installation are required. Availability of Qdrant (vector DB) in the `04-data` tier.
