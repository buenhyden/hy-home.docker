# AI Infrastructure Tier (08-ai) Requirements

## Overview

### Problem and Outcome

Cloud LLMs are costly and risk leaking data, there is no way to ground answers
in internal documents, and GPU resources have no central allocation. The
`08-ai` tier provides a privacy-hardened, self-hosted AI environment: a local
LLM inference engine (Ollama) on the host GPU and a chat and RAG interface
(Open WebUI) that keeps prompts and documents inside the platform.

### Stakeholders

- **AI engineer**: deploys models, tunes quantization and tunes the RAG
  pipeline.
- **Internal user**: chats with a local model for task help, document
  summaries and coding support, and uploads documents whose content then
  grounds the answers.
- **System agent**: calls the inference API for structured extraction or text
  analysis inside automated workflows.

The owner, @buenhyden, writes, reviews and accepts this package.

## Scope

### In Scope

- Local GPU inference and model storage, the chat and RAG
  interface with its embedding and vector store, and single sign-on access.

### Constraints and Exclusions

- **Owned elsewhere**: The other `08-ai` services (ComfyUI, Crawl4AI, MLflow
  and Open Notebook) are governed by REQ-0012 and their Stage 03 and Stage 05
  owners, not by this package.
- **Out of Scope**: Fine-tuning or pretraining large models, and serving an
  LLM API to external consumers.
- **Agent boundary**: An agent may list models, generate chat and embeddings
  and upload documents. It must not modify host files or send confidential
  prompts to the external internet. Answers are evaluated for faithfulness and
  relevance to the retrieved documents.

**Assumptions.**

The host has an NVIDIA GPU with its driver and container toolkit installed.

**Risks.**

- Insufficient GPU memory causes out-of-memory failures and interrupts
  service.

## Requirements

### Functional Requirements

- **REQ-0009-FR-0001**: Support GPU-accelerated inference.
- **REQ-0009-FR-0002**: Serve and manage multiple open-weight models (Ollama).
- **REQ-0009-FR-0003**: Provide a browser chat interface (Open WebUI).
- **REQ-0009-FR-0004**: Support a RAG pipeline with an embedding model and a vector store for internal document search.
- **REQ-0009-FR-0005**: Support multi-user access through the platform's single sign-on identity provider.

## Acceptance Criteria

### Acceptance Conditions

- **REQ-0009-FR-0001**: The inference engine reserves the host NVIDIA GPU. A
  time-to-first-token under 1 second for an 8B-parameter model is claimed only
  with separate runtime benchmark evidence.
- **REQ-0009-FR-0002**: Models persist across container recreation, and the
  engine exports metrics to the observability tier.
- **REQ-0009-FR-0003**: The chat interface is reachable through the gateway
  and uses the local inference engine as its model backend.
- **REQ-0009-FR-0004**: Embeddings are generated by the local inference
  engine, and vectors are kept in the chat interface's own persistent store;
  no prompt or document leaves the internal network.
- **REQ-0009-FR-0005**: Login goes through the identity provider with PKCE;
  automatic sign-up and account merging by email are disabled.

### Verification Method

The GPU reservation, model persistence, gateway route, local model backend, metrics export, embedding source and login settings are judged by reviewing the rendered configuration; that no prompt or document leaves the internal network (REQ-0009-FR-0004) is judged from the rendered network attachments and egress settings; the time-to-first-token claim is judged only from a separate runtime benchmark. No current Spec Package cites REQ-0009; a Spec that implements it records the evidence in its Task. The evidence is the review result and the benchmark output, recorded in that Task. The owner named in the frontmatter, @buenhyden, judges each condition from that evidence. The same owner accepts the requirement once every condition is judged met.
