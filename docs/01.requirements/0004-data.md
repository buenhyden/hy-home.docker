# Data Tier (04-data) Requirements

## Overview

The `04-data` tier holds the platform's state: relational, key-value cache,
object, search, graph and vector data. Managing these stores one by one
fragments access control and backup policy. The tier must give applications a
consistent way to persist data, keep it isolated from untrusted networks and
make it recoverable from backup.

## Scope

- **In scope**: deployment, backup and restore, network isolation and secret
  delivery for data services. Replication and failover are in scope only as
  standalone LAB exercises.
- **Out of scope**: business logic inside applications and building data
  migration tools.
- **Non-goal**: an embedded real-time visualization dashboard (Observability
  tier).

### Assumptions

- Applications reach a data service only over a network the two share.
- The host provides enough storage for the declared data roots.

### Risks

- HOME and DEV databases are single nodes with no failover, so recovery depends
  on backups.
- Multi-node LABs run on the same host and add memory and CPU load to it.

## Requirements

### Functional Requirements

- **REQ-0004-FR-0001**: HOME and DEV relational and key-value databases run as
  single nodes and are not highly available; their recovery path is backup and
  restore. Replication and failover are exercised only in standalone LABs,
  whose nodes share one host and therefore are not host-level high
  availability.
- **REQ-0004-FR-0002**: Data traffic must travel on dedicated internal data
  networks. A data service is reachable from outside those networks only
  through a declared exception: a host binding limited to loopback or the
  declared LAN address, or a gateway route that requires authentication, at the gateway or by the
  service itself.
- **REQ-0004-FR-0003**: Passwords and other sensitive values must be delivered
  as secret files, never as plaintext configuration or environment values.
- **REQ-0004-FR-0004**: Data must persist on host storage under the operator's
  declared data roots and survive container recreation.

### Stakeholders and User Needs

- **Backend developer**: stores and queries business data that can be restored
  from backup, and keeps session and temporary data in a low-latency cache.
- **Data engineer**: builds pipelines on S3-compatible object storage, search
  and graph stores.
- **AI service or agent**: searches vector embeddings for retrieval-augmented
  answers.

### Non-functional Requirements

No separately numbered non-functional requirement is defined.

### Interface Requirements

No separately numbered solution-independent external interface requirement is
defined.

## Acceptance Criteria

- **REQ-0004-FR-0001**: No document calls a single-node HOME or DEV database
  highly available. A LAB failover exercise records its observed failover time;
  a 30 second target applies only to that exercise.
- **REQ-0004-FR-0002**: Every published port of a data service binds to
  loopback or the declared LAN address, and every gateway route to a data
  service requires authentication, either a gateway access-control step or the
  service's own sign-in or request signature.
- **REQ-0004-FR-0003**: No data service declares a password or key as a
  plaintext configuration or environment value.
- **REQ-0004-FR-0004**: A restore from a backup copy returns the data without
  loss or corruption, verified by the restore check that the backup policy
  defines.
