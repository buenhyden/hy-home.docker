# 02-Auth Requirements

## Overview

### Problem and Outcome

The `02-auth` tier is the identity foundation of `hy-home.docker`. Many internal
services have no built-in authentication or keep their own user store, and
managing credentials per service is insecure and inefficient. The tier must
provide one identity provider, single sign-on across services, and a
gateway-side check that protects services which cannot authenticate users
themselves.

### Stakeholders

- **End user**: signs in once and reaches every permitted service without
  signing in again.
- **Service developer**: protects a service by requiring the gateway's single
  sign-on step, without writing authentication code.
- **Operator**: manages users and groups centrally and can require stronger
  authentication, such as multi-factor sign-in, for the administrator group.

The owner, @buenhyden, writes, reviews and accepts this package.

## Scope

### In Scope

- The central identity provider, the single sign-on check used by
  the gateway, durable identity storage and session storage.

### Constraints and Exclusions

- **Out of scope**: public social login unless it is configured as an upstream
  identity provider, and network-level isolation.
- **Non-goal**: replacing an application's own fine-grained permissions.

**Assumptions.**

- The gateway tier routes requests and calls the single sign-on check for routes
  that require it.
- The data tier provides the relational store for identity data and the
  key-value store for sessions.

**Risks.**

- Every protected route depends on this tier, so its outage blocks sign-in to
  all of them.
- The tier depends on the gateway for ingress and on the data tier for state.

## Requirements

### Functional Requirements

- **REQ-0002-FR-0001**: The system must provide a central identity provider
  that speaks OpenID Connect.
- **REQ-0002-FR-0002**: The system must provide a single sign-on check that the
  gateway calls per request: a browser without a valid session is sent to sign
  in, a non-browser client is refused with an authentication error, and a
  request with a valid session is admitted with the user's identity.
- **REQ-0002-FR-0003**: Sign-in sessions must be kept in a shared session store
  so that they survive a restart of the single sign-on check.
- **REQ-0002-FR-0004**: Identity data (users, groups, clients and realm
  configuration) must be kept in a durable, backed-up store.
- **REQ-0002-FR-0005**: Access through the single sign-on check must be limited
  by identity-provider group membership; currently only the administrator group
  is admitted.

## Acceptance Criteria

### Acceptance Conditions

- **REQ-0002-FR-0001**: A client completes an OpenID Connect sign-in against the
  identity provider.
- **REQ-0002-FR-0002**: On a route that requires single sign-on, an
  unauthenticated browser is redirected to sign in, an unauthenticated
  non-browser client receives an authentication error rather than a login page,
  and an authenticated request reaches the service. The check's latency is
  measured against a threshold the owning Task sets before measurement; no
  baseline is recorded here.
- **REQ-0002-FR-0003**: After the single sign-on check restarts, an existing
  valid session is still accepted.
- **REQ-0002-FR-0004**: Identity data survives a restart of the identity
  provider and is included in the data tier's backup.
- **REQ-0002-FR-0005**: A signed-in user outside the administrator group is
  refused on a single sign-on route.

### Verification Method

Each condition is judged by a runtime observation of the live Auth tier: a sign-in, a session, stored identity data and group membership, with the single sign-on check latency measured against a threshold the owning Task sets before measurement. No current Spec Package cites REQ-0002; a Spec that implements it records the evidence in its Task. The evidence is the observed result and measured latency, recorded in that Task. The owner named in the frontmatter, @buenhyden, judges each condition from that evidence. The same owner accepts the requirement once every condition is judged met.
