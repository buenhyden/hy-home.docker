## Execution Log

### Work Performed

#### Design before implementation

The current prompt router and resume hooks supply context. Add a standard
library brief check to their existing covered edit path. Use the observed
session request digest and revision, canonical workspace and Git baseline.
Persist only the minimal private hook state needed for consistency. The
planner authors the goal, non-goals, assumptions, acceptance, questions,
risk, allowed actions and checks as distinct fields. Preparing a brief
does not send another user question for a clear request.

Register the brief on the current session after read-only discovery. Check
absolute or relative edit targets as exact repository paths on enrolled
sessions. Require the explicit check before preparing a delegated write.
Keep unrelated read-only work outside the check. Recheck or invalidate the
record on a new request and on a resumed or compacted session. A material
question holds only its affected action. Hook refusal uses the supported
PreToolUse denial shape. The brief provides no authority and cannot
replace a user's authorization or native permission.

Avoid generic shell parsing, unconditional per-tool approval and shared
approval files. Native calls with unavailable scope stay coverage gaps.
Recover by reverting the bounded hook and planner changes together.
Test direct and literal nested edits, scope, request corrections,
questions, resume and compact, failed inputs, and no authority promotion.

#### Implementation and observation

Read D08, D03 and the supplied research entries S03, S06, S07, S10 and
S20–S23, plus the Docker binding profile, decisions and repository/PR
observations. Reused the accepted W01 implementation, native event
registrations, path decoder and independent approval policy. The actual
installed lookup reported Codex CLI 0.169.0 and Claude Code 2.1.325
through their `--version` commands. The GitHub PR lookup returned 1047
and 1048 open. No remote work was needed for local source verification.

The shared hook observes the native request without storing the prompt.
The standard-library CLI checks the current request revision, exact paths,
Git HEAD and declared material file digests. File-backed Task state changes
use the same exact path check. A material question holds its affected action.
An explicit handoff check requires both edit and dispatch scope for each
path. A null or unrelated reference can describe a plan but leaves mutation
blocked. An older reference can be reconsidered only within its previous
scope and identical material inputs after checking the actual authority.
No approval or reusable raw brief prose is written to the session state.

The independent revision marker invalidates old bindings before a competing
writer takes the snapshot lock. Consecutive compaction hooks can retain the
already bounded reference for reconsideration while leaving the brief
unbound. Regression inputs also reject added material files on reuse,
partially missing enrollment state and a repository Git config monitor.

Seven local dispatcher samples per build and prompt produced median before
and after values of 47.73 and 83.46 ms for the Claude-shaped
`UserPromptSubmit` and 51.36 and 86.04 ms for the Codex-shaped event.
The Claude-shaped recognized edit in an unenrolled session was 91.27 and
123.23 ms. These include shell and Python process startup and local load.
They do not measure native model feedback or user confirmation time.

#### Resume design

The direct W07 resume request rebinds this local work to clean
`04270eb86`. The manifest and the 56 focused tests passed again.
The active Codex session captured this request. After binding the exact
change paths, a deliberately inapplicable patch to the excluded README
was denied by the native PreToolUse hook before patch application.

A worker envelope currently carries a prepared request, but the explicit
check can implicitly use a newer registered brief for the same paths.
Require the caller to supply the prepared request revision and brief
revision, and compare both under the existing scope check. Supervisors
and resumed workers use the envelope values. A mismatch requires
reconciliation before mutation. Re-reading a fresh binding implicitly
would conceal the stale handoff. Update the canonical caller and existing
fixture tests together. Revert this bounded change to recover the old
command contract. Cover matching, missing, stale request and stale
brief revisions, including rebinds of the same path.

Provider payloads that explicitly identify a worker share the scope check,
but their prompt and lifecycle events must not replace the parent request.
Verify that separation with provider-shaped inputs. A separate live Codex
probe observed a revision change on the same digest and Git baseline and
the edit guard refused the old binding. Its exact lifecycle trigger was
unobserved.

#### Resume implementation and observations

The explicit dispatch check now requires both revisions from the prepared
envelope. Tests pair the same path with a superseded brief and a superseded
request. The previous scope-only invocation was accepted before the change
and is rejected by the new grammar. The canonical procedure requires the
same check before dispatch and before the delegated writer acts or resumes.
Its command contract had a breaking input change. The policy version is
3.0.0. The BriefRecord schema stays at 3.0.1.

The active managed Codex desktop session delivered UserPromptSubmit context
and a local CLI status read matched this workspace and baseline. A literal
patch nested in `exec` outside the enrolled scope was refused with a native
PreToolUse scope decision. An in-scope Task edit proceeded. The installed
Codex CLI reported 0.169.0. That version check identifies the CLI, while
the hook behavior identifies this desktop session. After rebinding the same
request, the explicit check refused the actual earlier brief revision.
No worker was launched for the mutation probe.
An edit after a same-digest revision rotation was denied until the same
authorized scope was rebound. Events explicitly carrying a worker agent
identifier no longer replace or invalidate the parent request, as the
synthetic regression verifies. The live rotation had no confirmed trigger.

Claude Code 2.1.325 was invoked with `--init-only`, project settings only,
empty MCP configuration and isolated configuration/state directories.
The local trace referenced SessionStart and the project hook, emitted a
trust or permission notice, and produced no evidence that the hook ran.
The startup probe made no model request. No trusted Claude behavior is
inferred from its exit status.

Seven interleaved local checks per build on the same enrolled synthetic Git
fixture measured median CLI wall time of 59.94 ms before and 58.96 ms after.
Both commands used the same launch form, interpreter and path input. The
small difference is not a native-session or provider-latency estimate.

### Blockers and Decisions

The record checks consistency. The provider remains the enforcement
authority. The current native matcher does not intercept arbitrary shell
writes, native dispatch or provider-internal Task transitions. Unenrolled
sessions lack the brief guard. Worker events that expose a parent session
and agent identifier can check both path tokens, but the hook has no
authenticated per-worker envelope or atomic link from its decision to a
later tool mutation. The controller retains these responsibilities.
