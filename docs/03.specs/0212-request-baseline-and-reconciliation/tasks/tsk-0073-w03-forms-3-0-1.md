#### Resumed verification and table boundary design

The 2026-11-16 continuation starts at `6056d8240`. The focused form and
version suite passed again after the W133 follow-up. The remaining form
gap is at the generic registered table boundary. A Postmortem action
header and rows without a Markdown delimiter can pass authored
validation. The same malformed block in a template can be projected as
a table contract.

Use the installed MarkdownIt table rule on the raw header and delimiter
in the template producer and the generic registered table validator.
Keep the existing column names,
alignment markers, row optionality and dedicated Plan, Task and README
reader responsibilities. A delimiter failure gets a specific document
diagnostic and prevents malformed source projection. This repairs the
existing Markdown boundary and leaves valid producer and consumer shapes
intact, including delimiters with optional outer pipes. Test both paths
and recheck the active corpus. Reverting this change restores the former
parser behavior.

The continued baseline ran 149 focused tests in 41.185 seconds. The
final run of the same module selection took 43.967 seconds with 152
tests, an increase of 2.782 seconds including three added tests. The
final run overlapped the corpus check.

#### Conditional subsection content

The renewed D01 3.0.1 comparison at `3331374a3` found a content
boundary gap. The placeholder check skips only whole lines beginning
with a comment, so an inline annotation can make a bare `N/A` pass.
Use the existing parsed top-level headings to bound each section.
Parse plausible placeholder bodies with MarkdownIt. Ignore recognized
HTML comments, including blocks ending at EOF, and containers that
contain only those comments. Visible explanations, code and nonempty
quotes count as content. An omitted optional section remains valid.
The Registry, templates and role shapes retain their existing contracts.
Reverting this source unit restores the former placeholder check.

The same focused module selection ran 154 tests in 39.640 seconds at
the baseline and 156 in 41.101 seconds at the final candidate. The
sample includes two added tests and concurrent local validation.

#### Spec Package example boundary

The continuation at `cf2b63baa` found a D01 reader mismatch. A raw HTML
block with a Markdown-shaped numbered line is invisible to the form
reader but can supply an acceptance criterion to the Spec Package
reader. A fake duplicate heading can also make a valid section unreadable.

Use the existing Markdown form line view at the evidence reader
boundary. Keep the registered heading names, legacy H2 bindings, and
line-based inline comment handling. Compute comment state on the source
before hiding examples so a delimiter inside raw HTML can still affect
the surrounding lines. Preserve the exact raw-byte reader
used to compare historical Task migrations. Examples leave a boundary
between the lines before and after them. This preserves authored
criterion and evidence semantics. Confirm ordinary and legacy sections,
reject example-only sections, and run the corpus lifecycle check.
Revert the source unit to restore the former reader.
