### Work Performed

#### Design before implementation

Trace installed commit and push checks, local authoring commands and the
hosted PR candidate jobs to their registered leaves, checkout and actual
evidence consumers. Preserve existing accepted controls. For the document
CLI, reuse immutable parse, classification and Git observations inside
the run at the narrowest safe boundary. In particular, pass the already
validated Registry to command path classification so that active and
terminal Tasks use the same immutable input. Keep the current permission,
unsafe-path and historical evidence checks and their diagnostics.

Candidate dispatch and execution must share the expected nonempty plan.
A selected hosted execution with missing required results or a changed
input must fail closed. Unselected planning remains observable as such.
Use existing plan and evidence owners and verify both normal and negative
inputs. Prefer an invocation-local object over cross-run caching, and
prefer existing targeted selection over a second selector. Revert the
bounded changes to restore the previous implementation. Measure the same
local inputs before and after, and report hosted and runtime observations
only if obtained.

#### Delivery and feedback routes

| Event or entry | Actual executable path | Input and consumer |
| --- | --- | --- |

Keep the installed staged and ref guards, the hosted candidate provenance
and toolchain checks, and the main security lane. The corpus metadata and
lifecycle leaves check authored content. The registered validator regression
leaves check the implementation and its schemas, and select their owner
paths separately. The all-link corpus leaf keeps the canonical local-only
scope. Unknown changed paths block with a routing error. Rename and delete
handling retain the Git change closure and use the same selector.

#### Implementation and measurements

- The link CLI creates one bounded current graph and admits documents from
  their parsed status. Its graph carries the checked root's validated
  Registry for the link modes. Historical link verification keeps its
  provenance and retired-package checks. The old historical path list
  always duplicated the current list and did not admit out-of-scope files.
- Each normal metadata invocation lazily compiles one bounded frontmatter
  schema per source and shares the validator through its current
  validation passes. Alternate root and standalone inputs still have their
  own schema boundaries. No result cache crosses invocations.
- The candidate runner requires a seeded plan for dispatched hosted work.
  Empty execution plans and incomplete or non-PASS result rows cannot
  return success. The fixed aggregate consumes each shard's applicability,
  job result and actual validation step outcome. The workflow contract
  enforces those routes. See [GitHub Actions step outcomes](https://docs.github.com/en/actions/reference/workflows-and-actions/contexts#steps-context).
- The typed selector routes ordinary documentation, validator inputs and
  delegated test owners separately. All 2,016 tracked paths including this
  Task have an explicit route. The
  docs index moved from 47 to 8 hosted leaves and 34 to 7 local leaves.
  A requirement edit moved from 9 to 8 hosted leaves, with 7 local leaves
  unchanged. A Registry or schema edit selects 11 hosted leaves including
  the three validator regression leaves. Explicit full remains available.

The command-path benchmark used Python 3.12.3, Git 2.43.0 and the same 877
document inputs from `ab099dee2`, without dependency installation. The
candidate harness overlaid the original bytes of the two edited documents
and excluded the new Task. The baseline wall time was 600.63 seconds
and the final candidate time was 15.864 seconds. The candidate recorded
one Git inventory in 0.023 seconds, one bounded read and parse stage in
11.191 seconds, and 2.509 seconds inside the command leaf. Each reported
8,593 links and zero findings. These are single local observations under
varying concurrent load, so they establish the observed improvement on
that input without a percentile or a hosted forecast.

The schema phase used identical 46 tracked documents and four injected
inputs. Three alternating samples gave medians of 3.9910 and 0.0752
seconds, with identical findings and three invalid inputs detected. The
same one-path metadata CLI check used 255.09 versus 205.27 CPU seconds
and 256.43 versus 257.56 wall seconds. The sample showed lower CPU cost
and did not show lower whole-command wall time. Host wait, repeated
metadata Git reads and independent validation passes remain to measure.

#### Continuation results

The native and outer metadata passes retain their own candidate sets and
share parsed current records for their overlap. The exact merge-base text
is kept separate from moved-document aliases and reused by body and
version comparisons. A generation-source batch now exposes the verified
raw bytes for eligible terminal Tasks. Current files must still match
byte for byte through the bounded regular-file reader. The generation
ancestor lookup reuses only successful results for a resolved repository,
exact current HEAD commit and generation, within one validation invocation.

The paired one-path metadata sample loaded the prior and new validator
code against the same working tree and merge base `863d33d27`, with
REQ-0004 selected explicitly. A local instrumented subprocess wrapper
counted actual Git children. Both runs selected one record with zero
violations and zero transition overrides. Wall time was 188.10 to 126.09
seconds and CPU time was 184.78 to 124.25 seconds. Git children fell from
13,555 to 7,072 and record parses from 2,958 to 2,167.

A separate four-call phase at the same HEAD returned the same generation
source `49f8dd661acf`. It went from four first-parent walks and 2,144
Registry reads in 52.592 seconds to one walk and 536 reads in 12.982
seconds. Each comparison has one paired sample. Local contention can
affect wall time. The remaining Git children were counted without claiming
that every one is unique. Neither experiment ran on hosted Actions.
