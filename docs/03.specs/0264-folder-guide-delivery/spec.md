# Folder Guide Delivery Specification

## Overview

### Intent

Nine folders carry an `AGENTS.md` guide, but neither Codex nor Claude Code reads
them when an agent works below the folder. This Spec contracts how each
provider receives the nearest folder guide: Claude Code through a generated
folder `CLAUDE.md` import shim, Codex through one shared hook.

### Background

The owner requested on 2026-11-06 that Codex and Claude read each folder's
`AGENTS.md`, and first chose one shared hook over folder `CLAUDE.md` shims.
Later on 2026-11-06 the owner amended that choice to a shim for Claude and the
hook for Codex ("Claude는 shim, Codex는 hook"), so this Spec returned to review.

- Codex merges `AGENTS.md` only from the repository root down to the working
  directory (`codex-rs/core/src/agents_md.rs` in openai/codex).
- Claude Code reads `AGENTS.md` only where no `CLAUDE.md` is on the path. Root
  `CLAUDE.md` exists here, and the setting to read both is ignored in project
  settings (code.claude.com/docs/en/memory).

So neither provider reads the folder guides on its own. Claude Code does load
a nested `CLAUDE.md` on demand when it reads a file below it, and again after
compaction, and expands an `@AGENTS.md` import in it. Headless Claude Code
2.1.319 loaded a folder `CLAUDE.md` holding `@AGENTS.md` on a first Read and on
a Write without a prior Read, also when the renderer marker comment and a
heading precede the import.

## Scope

### In Scope

- `scripts/lib/hooks/folder_guides.py` and `scripts/hooks/agent-event-hook.sh`.
- The tests in `tests/lib/hooks/test_folder_guides.py` and the script manifest
  entry.
- The folder `CLAUDE.md` import shims, generated by
  `scripts/operations/provider_surface_renderer.py`, the stage validators that
  admit them, and their renderer tests.
- The folder guide rule in `.agents/governance/documentation-protocol.md`.
- The `.claude/provider.md` and `.codex/provider.md` descriptions.
- The audit of the folder `AGENTS.md` files in the same branch.

### Out of Scope

- A shim at the root; root `CLAUDE.md` stays the bootstrap entry shim.
- Delivery on a Codex shell read; only `apply_patch` triggers delivery.
- Changing what a guide says beyond the audit.

## Contracts

### Normal Behavior

Every Git-tracked folder `AGENTS.md` below the root has a generated `CLAUDE.md`
beside it: the renderer marker comment, a `# <folder> Folder Guide` heading
and `@AGENTS.md`. Claude
Code loads that shim, and so the guide, natively. The renderer's `--check`
reports a missing, drifted or stale shim; `--write` creates a missing one and
quarantines one whose guide is gone.

For Claude the PreToolUse hook delivers no guide content. It adds a one-line
reminder naming the nearest folder guide on each edit, and after a SessionStart
`compact` or `resume` an instruction to re-read it. For Codex the hook adds the
full nearest folder guide to `additionalContext` once per session, the first
time `apply_patch` touches a file below it, plus the same reminders. The root
`AGENTS.md` is never delivered.

### Error Behavior

The hook never blocks a tool call. Any failure in guide lookup, state access or
reading leaves the tool call allowed and delivers nothing. The renderer never
overwrites a folder `CLAUDE.md` that lacks its marker; `--write` stops with an
error instead.

### Boundary Behavior

A guide larger than 16 KiB is capped. State lives under
`$XDG_STATE_HOME/hy-home/folder-guides`, default `~/.local/state`, and is
replaced atomically.

### Constraints

The state directory must be owned by the current user with mode 0700, else it
is not used. The hook adds no tool permission or approval.

## Acceptance Criteria

1. Before an edit below a folder with an `AGENTS.md`, Codex (`apply_patch`)
   receives that guide in `additionalContext`, and Claude receives it through
   the folder `CLAUDE.md` shim.
2. The hook delivers a guide's content once per session; on each edit it adds
   a one-line reminder, and after SessionStart `compact` or `resume` a re-read
   instruction.
3. The root `AGENTS.md` is never delivered.
4. The hook never blocks a tool call, including on state or read failure.
5. State is kept in a per-user directory owned by the user with mode 0700, and
   written by atomic replace.
6. `.claude/provider.md` and `.codex/provider.md` describe the delivery and its
   limits.
7. The folder `AGENTS.md` files are audited in the same branch.
8. The delivery is observed in a new Claude session and a new Codex
   session started at the repository root: in Claude, reading a file under
   `infra/` loads `infra/CLAUDE.md` with `infra/AGENTS.md`; in Codex, editing a
   file under `infra/` shows the "Folder guide `infra/AGENTS.md`" context once.
9. The renderer generates the `@AGENTS.md` shim beside every Git-tracked folder
   guide and none at the root; `--check` reports a missing, drifted or stale
   shim; `--write` creates it, quarantines a stale one, and never overwrites a
   hand-written folder `CLAUDE.md`.
10. The metadata, link, agent governance and script manifest checks and the
    stage loaders accept the shims.

## Failure Conditions

### Observable Failures

- A guide missing before an edit, or repeated within a session.
- A folder guide without its shim, or a shim without its guide, passing
  `provider_surface_renderer.py --check`.
- The root guide delivered.
- A tool call blocked by the hook.
- State in a directory not owned by the user or not mode 0700.

### Stop Boundaries

A Codex shell read does not trigger delivery. Native delivery in a live
session is not yet observed; only dispatcher tests exist until criterion 8 is
accepted.
