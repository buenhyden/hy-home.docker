# k6 Load Test Recovery Runbook

## When to Use

승인된 k6 test를 실행할 때, 또는 k6가 잘못된 endpoint를 대상으로 하거나, 합의된
limit을 초과하거나, 결과 export에 실패하거나, 예기치 않게 종료될 때 이 절차를 사용한다.
Command는 저장소 루트에서 실행하며 `k6`만 지정한다.

## Procedure

### Approved Live Run

target owner가 target, traffic ceiling, stop condition, script를 승인한 뒤
([Guide](../guides/0061-k6.md#normal-use)), job만 시작하고 로그를 확인한다.

```bash
docker compose --profile testing up --no-deps --abort-on-container-exit k6
docker compose --profile testing logs --tail=200 k6
```

### Recovery

1. 새 load를 먼저 중지한다.

   ```bash
   docker compose --profile testing stop k6
   docker compose --profile testing ps k6
   ```

2. target-side latency, error, saturation signal로 target 회복을 확인한다. impact가
   설명되지 않은 상태에서는 재시작하지 않는다.
3. sanitized job evidence를 캡처한다.

   ```bash
   docker compose --profile testing logs --tail=200 k6
   ```

   target, `K6_SCRIPT`, `K6_TESTID`, image declaration, start/stop 시각, exit code,
   target 회복 여부를 기록한다. credential이나 response body는 기록하지 않는다.
4. metric이 없으면 시나리오를 변경하기 전에 설정된 remote-write endpoint와 수신 측
   Prometheus를 확인한다. local job이 완료되었다는 사실만으로 result retention을 증명할 수 없다.
5. scenario나 image 변경이 실패 원인이면 마지막으로 검토된 Git version으로 복원하고
   static check를 실행한 뒤, 실제 test 재실행 승인을 받기 전에 disposable low-load
   target을 사용한다.

### Verification

```bash
bash scripts/hardening/check-all-hardening.sh 09-tooling
HYHOME_COMPOSE_PROFILES=testing bash scripts/validation/validate-docker-compose.sh
```

k6가 중지되거나 종료되고 target signal이 합의된 범위로 돌아오고 보존된 evidence로
결과가 Prometheus에 도달했는지 식별할 수 있을 때만 recovery가 완료된 것이다.

### Backup and Recovery Status

영구적인 job-container restore는 없다. version-controlled script는 Git에서
복원되며, 보존된 metric은 Prometheus backup 절차에 따라 복구한다. 이 절차는 계획된
문서이며 2026-09-20 correction 중에는 실행되지 않았다.

## Evidence

approval, target, scenario commit, test ID, image declaration, timestamp, exit code,
sanitized summary, result-retention status, target-side recovery를 기록한다.
credential이나 response body는 절대 캡처하지 않는다.

## Rollback or Recovery

job을 중지하고, 마지막으로 검토된 Git commit에서 scenario를 복원하며, 수신 측
Prometheus 절차에 따라 보존된 metric을 복구한다. 원래 target에 대한 승인을 받기 전에는
disposable target에만 재실행한다.

## Escalation

job을 중지할 수 없거나, 중지 후에도 traffic이 계속되거나, target signal이 회복되지
않거나, credential이 노출되었을 수 있거나, result retention이 필요한데 수신 측
backend를 사용할 수 없을 때 escalation한다.
