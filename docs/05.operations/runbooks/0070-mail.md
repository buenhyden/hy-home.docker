# Stalwart Mail Runbook

## When to Use

Use for listener/auth/TLS/DNS/queue failures, mailbox/config recovery, or an
approved upgrade. Work from the root and use synthetic mail only.

## Procedure

1. Validate and capture bounded state:

   ```bash
   docker compose --profile mail-server config --quiet
   docker compose --profile mail-server ps stalwart
   docker compose --profile mail-server logs --tail=200 stalwart
   ```

2. Separate management UI, SMTP/submission, IMAPS and configuration symptoms.
   A listener that is missing or extra after a restart means the plan did not
   apply: `docker compose --profile mail-server run --rm stalwart-config`,
   then restart `stalwart`. Relay attempts must be refused with SMTP `550` and
   `Relay not allowed`. Redact addresses, subjects, bodies, tokens, and credentials.
3. Verify listener certificate/SNI, auth and relay policy, DNS records, disk, and
   actual configured storage backends. Do not treat an SMTP socket as safe relay.
4. Restart only Stalwart after storage/listener checks. Verify relay denial and
   one approved synthetic submission/retrieval before external delivery.

### Backup and isolated restore

1. Inventory data/blob/search/in-memory backends and configuration/certificate/
   DKIM custody. Block new submissions and drain or record the queue.
2. Use the running version's documented CLI snapshot/export for management
   objects when supported, and each backend's consistent backup. If local-only
   storage lacks an online snapshot, stop Stalwart and copy all of `/var/lib/stalwart`
   (`stalwart --export <path>` with the server stopped is the native export).
3. Restore to isolated storage and a non-delivery hostname/network with outbound
   SMTP blocked. Supply replacement credentials and certificates.
4. Verify config/account/mailbox counts, synthetic IMAP retrieval, auth/relay
   denial, and queue state. Enable delivery only after DNS and owner review.

### Upgrade

Take the backup above, review release/storage/license notes, test the target
image on restored data, and exercise every used listener. On incompatibility,
stop the target and restore both prior image and pre-upgrade data.

## Evidence

Record exits, listener/TLS/DNS booleans, backend types, backup IDs/checksums,
counts, synthetic test IDs, release/source commit, and final state only.

## Rollback or Recovery

Backup/restore, delivery, and upgrade rehearsal are **planned but unexecuted**.
Do not copy a live unknown database or enable outbound delivery during rehearsal.

## Escalation

Stop on open-relay behavior, unknown backend, missing backup/key custody, real
mail in a test, DNS/reputation issues, or incompatible schema/license behavior.
