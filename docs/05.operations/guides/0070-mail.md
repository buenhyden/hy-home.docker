# Stalwart Mail Server Guide

## Usage

### 목적과 분류

Stalwart는 OPTIONAL 내부 메일 서버이다. `mail-server`에서만 선택되며 Mailpit
캡처와는 구분된다. 호스트 포트가 없다. `mail_net`의 컨테이너만 메일을 제출할 수
있으며 웹 admin과 JMAP은 SSO 뒤에서 Traefik으로 라우팅된다. 릴레이는 전혀 하지
않는다. 설정된 도메인 외부의 수신자는 거부된다.

### 현재 구현

- [Stalwart Compose](../../../infra/10-communication/stalwart/docker-compose.yml)는
  읽기 전용 root, `cap_drop:
  ALL` plus `NET_BIND_SERVICE`(바이너리 파일 capability)만으로, 호스트 포트 없이
  자체 사용자(UID 2000)로 이미지를 실행한다.
- `config/config.json`은 datastore만 지정한다(`/var/lib/stalwart`의 RocksDB,
  `${DEFAULT_COMMUNICATION_DIR}/stalwart/data`에서 바인드됨). 나머지는 모두
  datastore에 저장된다.
- `stalwart-config`는 pin된 `stalwart-cli`로
  [config/plan.ndjson](../../../infra/10-communication/stalwart/config/plan.ndjson)을
  적용한다: 도메인 `${DEFAULT_URL}`, 호스트 이름 `mail.${DEFAULT_URL}`, 정확히
  4개의 listener(SMTP 25, submission 587, IMAPS 993, HTTP 8080),
  `allowRelaying = false`. upsert, update, reconcile을 수행하므로 재실행하면 수렴한다. listener
  변경은 다음 Stalwart 재시작 시 적용된다.
- `stalwart_password`(COMM-006)는 서버와 job 프로세스 내부에서만 복구용 admin이
  되며, Compose 파일에는 credential이 없다.
- 587/993의 TLS는 Certificate 객체가 설정되기 전까지 Stalwart의 기본 인증서를
  사용한다. `mail_net`의 클라이언트는 이를 명시적으로 신뢰해야 한다.
- healthcheck는 8080의 `/healthz/live`를 읽으며, 이는 배달 준비 상태가 아니라
  프로세스 liveness이다.
- 이 이미지는 업스트림에서 AGPL-3.0 또는 Stalwart Enterprise License로 이중
  라이선스된다. 추적되는 라이선스 키가 없으므로 Enterprise 기능은 증명되지 않는다.
  이에 의존하지 않는다.

### 일반적인 사용과 전제 조건

1. `${DEFAULT_COMMUNICATION_DIR}/stalwart/data`를 비어 있는 상태로 생성한다.
   Docker가 첫 시작 시 이미지 사용자의 소유권을 부여한다.
2. `docker compose --profile mail-server up -d stalwart`를 실행한 다음
   `docker compose --profile mail-server run --rm stalwart-config`, 그다음
   `docker compose --profile mail-server restart stalwart`를 실행한다.
3. admin UI나 추가 plan을 통해 계정을 생성한다. 합성 메일을 사용하고 본문이나
   credential을 증거에 절대 기록하지 않는다.
4. 외부 배달에는 새로 승인된 요구 사항(DNS, SPF, DKIM, DMARC, 평판)과 릴레이
   규칙에 대한 검토된 변경이 필요하다.

### 백업과 업그레이드

가능하면 버전이 지원하는 Stalwart CLI 스냅샷/export를 설정 객체에 사용하고,
설정된 각 데이터/blob/검색 백엔드에는 네이티브 백업 방법을 사용한다. 배포가
로컬 bind 기반 저장소만 사용하고 온라인 일관성 export가 없다면, Stalwart를
중지하고 메타데이터와 함께 `/var/lib/stalwart` 트리 전체를 복사한다
(`stalwart --export`가 네이티브 export이다). 인증서/개인 키 보관과 DNS/DKIM
레코드는 별도로 보존한다. outbound SMTP를 차단한 격리된 호스트 이름에서
복원하고, 계정/mailbox 수와 합성 조회를 검증한 다음 전환을 승인한다.

업그레이드 전에는 그 백업을 확보하고 테스트하며, release/스토리지/라이선스
노트를 읽고, 호환 이미지를 pin하고, 모든 listener를 검증한다. 이 문서 작업에서는
배달, 백업, 복원, 업그레이드를 실행하지 않았다.
