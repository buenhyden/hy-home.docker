# Stalwart Mail Server Guide

## Usage

### 목적과 분류

Stalwart는 OPTIONAL 내부 메일 서버이다. `mail-server`에서만 선택되며 Mailpit
캡처와는 구분된다. 호스트 포트가 없다. 현재 서버는 `mail_net`과 `edge_net`에 함께 연결되어 있으므로 두 네트워크의
peer 접근을 확인해야 하며 웹 admin과 JMAP은 SSO 뒤에서 Traefik으로 라우팅된다. 릴레이는 전혀 하지
않는다. 설정된 도메인 외부의 수신자는 거부된다.

### 현재 구현

- [Stalwart Compose](../../../infra/10-communication/stalwart/docker-compose.yml)는
  읽기 전용 root, `cap_drop:
  ALL`과 `NET_BIND_SERVICE`(바이너리 파일 capability)만으로, 호스트 포트 없이
  자체 사용자(UID 2000)로 이미지를 실행한다.
- `config/config.json`은 datastore만 지정한다(`/var/lib/stalwart`의 RocksDB,
  `${DEFAULT_COMMUNICATION_DIR}/stalwart/data`에서 바인드됨). 나머지는 모두
  datastore에 저장된다.
- `stalwart-config`는 pin된 `stalwart-cli`로
  [config/plan.ndjson](../../../infra/10-communication/stalwart/config/plan.ndjson)을
  적용한다: 도메인 `${DEFAULT_URL}`, 호스트 이름 `mail.${DEFAULT_URL}`, 정확히
  4개의 listener(SMTP 25, submission 587, IMAPS 993, HTTP 8080),
  `allowRelaying = false`. listener 집합 전체를 reconcile하므로 plan에 없는 listener를
  삭제할 수 있다. 일치하는 객체는 patch되며 순차 적용 중 일부만 반영될 수 있다.
  재실행은 진단이나 자동 롤백이 아니다. listener 변경은 다음 서버 재시작 때 적용된다.
- `stalwart_password`(COMM-006)는 서버와 job 프로세스 내부에서만 복구용 admin이
  되며, Compose 파일에는 credential이 없다.
- 587/993의 TLS는 Certificate 객체가 설정되기 전까지 Stalwart의 기본 인증서를
  사용한다. `mail_net`의 클라이언트는 이를 명시적으로 신뢰해야 한다.
- healthcheck는 8080의 `/healthz/live`를 읽으며, 이는 배달 준비 상태가 아니라
  프로세스 liveness이다.
- 이 이미지는 업스트림에서 AGPL-3.0 또는 Stalwart Enterprise License로 이중
  라이선스된다. 추적되는 라이선스 키가 없으므로 Enterprise 기능은 증명되지 않는다.
  이에 의존하지 않는다.

### 일반적인 사용과 전제 조건

실행 순서와 실패·복구 판단은 [런북](../runbooks/0070-mail.md)의 `승인된 최초 기동` 절차를 따른다. 데이터와 권한 경계는 해당 정책을 유지한다.

### 백업과 업그레이드

실행 순서와 실패·복구 판단은 [런북](../runbooks/0070-mail.md)의 `보존 대상과 변경 검토` 절차를 따른다. 데이터와 권한 경계는 해당 정책을 유지한다.

## Common Checks

- `docker compose --profile mail-server config --quiet`
- `docker compose --profile mail-server config --services`
- `bash scripts/hardening/check-all-hardening.sh 10-communication`

## Runbook Handoff

listener 실패, 데이터 복구, 업그레이드에는 [runbook](../runbooks/0070-mail.md)을
사용한다.

### 소스 검토의 한계

여기서 설명한 네트워크는 선언상 연결 가능한 경로다. 실제 peer 연결·인터넷 공개·
사용자 인증·복구 성공을 이번 문서 작업에서 시험하지 않았다. 현재 선언의 제한을
해소하는 구현 변경은 별도 승인·보안 검토·검증이 필요하다.
