# Neo4j Usage Guide

## Usage

### Overview

이 문서는 root compose에 active include된 [Neo4j Compose 구현](../../../infra/04-data/neo4j/docker-compose.yml)을 설명한다. 현재 구현은 `OPTIONAL` 단일 Community `neo4j` 서비스, exact `graph` profile, `edge_net`, `neo4j_password` Docker Secret, secret-aware entrypoint와 Traefik Browser route를 사용한다.

### Current implementation

| 항목 | 이 저장소의 구현 결정 |
| --- | --- |
| Consumer와 data 근거 | Cypher 관계가 필요한 consumer를 위한 OPTIONAL graph storage이며 cluster 요구는 구현되어 있지 않다. |
| Source·update 책임 | [Compose](../../../infra/04-data/neo4j/docker-compose.yml)와 secret을 처리하는 entrypoint가 Community image/process를 소유한다. update 시 edition 호환성을 검토한다. |
| 서비스·profile | 단일 `neo4j`; 정확한 profile은 `graph`. |
| 흐름·노출 | application은 내부 Bolt를 사용하고 Browser는 Traefik HTTPS를 사용한다. public Bolt router는 없다. |
| 영속성·secret | `neo4j-data:/data`와 `neo4j_password` Docker Secret을 사용한다. |
| Health·자원 | secret을 사용하는 `cypher-shell RETURN 1`; `template-stateful-med`와 Compose heap/page-cache 통제를 적용한다. |
| 보안 | Community 인증, secret을 처리하는 entrypoint와 Browser gateway 경계를 사용한다. |
| Backup·upgrade | Community offline dump/load만 사용하며 Enterprise online backup은 사용할 수 없다. store-format upgrade/제거 전에 restore-test를 수행한다. |
| License·edition | Neo4j Community에는 GPLv3가 적용된다. Enterprise backup/clustering 명령과 사용 권한까지 제공된다는 뜻은 아니다. |

### Identity-specific behavior

Neo4j5.26.30 Community 는 secret-aware wrapper 로 NEO4J_AUTH 를 준비한다. initial password input 은 이미 생성된 system auth store 의 rotation 절차가 아니다. Bolt 와 Browser path 및 certificate 는 서로 다른 점검 대상이다. 노출 선언 2004 만으로 Community metrics 가 실제 제공된다고 가정하지 않는다. Community offline dump/load 와 constraints/index/graph invariants 를 사용하고 Enterprise online backup/cluster 절차를 적용하지 않는다.

| 정확한 식별자 | 목적·상태·기동 차이 | 준비 상태 판단의 한계 | 구현 소유자 |
| --- | --- | --- | --- |
| `neo4j` | Community graph; offline dump/load와 system auth store | 선언된 역할별 health; 사용자 기능 별도 | [선택·의존·접속·입력·mount](../../../infra/04-data/neo4j/docker-compose.yml) |

선택 profile, version, port, 환경 입력, secret identifier와 mount의 정확한 값은 각 행의 구현이 소유한다. [공통 template](../../../infra/common-optimizations.yml)의 resource·security 상속과 서비스 override를 함께 읽는다. 값의2026-10-01 source snapshot과 official version/build 검토는 [W4 Task](../../03.specs/0198-operations-documentation-system/tasks/tsk-0004-data-messaging-analytics.md)에 보존했다. 반복OOM, disk/WAL/checkpoint 증가와 metrics 누락은 capacity 검토 trigger이며 health는 사용자 기능이나 복원을 증명하지 않는다.

### Purpose

Neo4j를 graph storage로 사용할 때 현재 repository의 service name, route, Bolt boundary, secret mount, healthcheck 기준을 오해하지 않도록 한다.

### Prerequisites

- 루트 [docker-compose.yml](../../../docker-compose.yml)에 `infra/04-data/neo4j/docker-compose.yml`가 active include인지 확인한다.
- `DEFAULT_DATA_DIR`, `DEFAULT_URL`, `NEO4J_BOLT_PORT`, `NEO4J_HTTP_PORT`, `neo4j_password` secret 파일이 준비되어 있어야 한다.
- 운영 점검은 승인된 credential custody와 비공개 실제 TTY에서 client의 native password prompt를 사용한다. Password를 URL·argv·환경 변수·history·문서·로그에 넣지 않으며 custody/TTY가 없으면 중단한다.

### Step-by-step Instructions

정상 운영 중 점검은 compose profile 렌더링, 서비스 상태, Traefik HTTP router 기준 Browser route(`https://neo4j.${DEFAULT_URL}`), container-local client의 native password prompt를 통한 Bolt `RETURN 1` 확인으로 구성된다. 애플리케이션이 `edge_net` 내부에서 접근할 때는 `bolt://neo4j:${NEO4J_BOLT_PORT:-7687}`를 기준으로 한다. Public Bolt TCP route는 현재 compose에 선언되어 있지 않으므로 별도 gateway 변경 승인 없이는 문서화하지 않는다. 실행 가능한 명령 순서와 기대 결과는 [Neo4j runbook](../runbooks/0033-neo4j.md#steps)을 따른다.

### Common Pitfalls

- 현재 구현은 Community single service다. clustering, multi-database enterprise operations, public Bolt routing을 구현된 기능처럼 설명하지 않는다.
- Neo4j Browser는 Traefik HTTPS route를 통해 `${NEO4J_HTTP_PORT:-7474}`로 전달된다. `${NEO4J_HTTPS_PORT:-7473}` exposed port가 있어도 별도 HTTPS router가 선언된 것은 아니다.
- `neo4j_password` 값은 entrypoint와 healthcheck가 secret mount에서 읽는다. Source healthcheck의 password argv 노출은 별도 구현 nonconformance이며 운영 점검에서 같은 방식을 사용하지 않는다.
- Community edition 복구는 offline `neo4j-admin database dump/load` 절차를 사용한다. Enterprise용 문서에 설명된 online backup 기능을 여기서 사용할 수 있다고 서술하지 않는다.

## Common Checks

- `docker compose --profile graph config --quiet`
- `docker compose ps neo4j`
- Bolt `RETURN 1` 확인은 [Neo4j runbook의 private TTY/native-prompt 절차](../runbooks/0033-neo4j.md#steps)를 따른다. Secret 파일을 읽어 password argv로 확장하는 대체 명령은 허용하지 않는다.
