# k6 Usage Guide

## Usage

k6는 `testing`에서만 선택되는 **DEV** one-shot load generator다. Root Compose
project가 leaf를 포함하고, `${DEFAULT_TOOLING_DIR}/k6`를 read-only로 `/scripts`에
mount하며, `${K6_SCRIPT:-smoke.js}`를 실행하고, metrics를 설정된 Prometheus
remote-write endpoint로 export한다. Port를 publish하지 않으며 health state도 없다.

### Implementation Sources

- [k6 Compose](../../../infra/09-tooling/k6/docker-compose.yml)
- [k6 Dockerfile](../../../infra/09-tooling/k6/Dockerfile)
- [k6 dashboard](../../../infra/06-observability/grafana/dashboards/Infrastructure/k6.json)

Dockerfile과 Compose 선언이 image version을 소유한다. Bind-mount된 script가
workload를 소유하며, `K6_TESTID`가 run을 식별한다. `restart: "no"`는 완료된 test가
다시 시작되지 않게 막는다. Prometheus는 declared k6 dependency가 아니라 remote-write
stream의 external consumer이므로, metrics retention이 필요하면 먼저 준비해야 한다.

### Normal Use

1. Target owner와 함께 target, traffic ceiling, stop condition, credential, test
   script를 검토한다. Default smoke test를 production에 겨냥하지 않는다.
2. Project root에서 repository check을 실행한다.

   ```bash
   bash scripts/hardening/check-all-hardening.sh 09-tooling
   HYHOME_COMPOSE_PROFILES=testing bash scripts/validation/validate-docker-compose.sh
   ```

3. 승인된 live test는 [k6 Runbook](../runbooks/0061-k6.md#approved-live-run)을
   따른다.

4. Summary와 exit code를 target-side latency, error, saturation과 연관지어
   확인한다. Rendered service나 시작된 container가 target readiness를 뜻하지는 않는다.

### State and Upgrade

Service 자체는 disposable하다. Version-controlled scenario와 보존되는
result/evidence store를 backup한다. Prometheus가 remote-write retention을
소유한다. Image upgrade 전에 k6 release note를 검토하고, disposable target에
대해 low-load canary를 실행하며, dashboard가 사용하는 output name을 확인한다.
Result semantics가 바뀌면 image pin과 scenario를 함께 roll back한다.

## Common Checks

- `bash scripts/hardening/check-all-hardening.sh 09-tooling`
- `HYHOME_COMPOSE_PROFILES=testing bash scripts/validation/validate-docker-compose.sh`
- 승인된 run에서는 `k6` exit code, sanitized summary, 수신된 Prometheus evidence,
  target-side recovery signal을 확인한다.
