# k6 Usage Guide

## Usage

k6 is a **DEV** one-shot load generator selected only by `testing`. The root Compose
project includes the leaf, mounts `${DEFAULT_TOOLING_DIR}/k6` read-only at
`/scripts`, runs `${K6_SCRIPT:-smoke.js}`, and exports metrics to the configured
Prometheus remote-write endpoint. It publishes no port and has no health state.

### Implementation Sources

- [k6 Compose](../../../infra/09-tooling/k6/docker-compose.yml)
- [k6 Dockerfile](../../../infra/09-tooling/k6/Dockerfile)
- [k6 dashboard](../../../infra/06-observability/grafana/dashboards/Infrastructure/k6.json)

The Dockerfile and Compose declaration own the image version. The bind-mounted
scripts own the workload; `K6_TESTID` identifies a run. `restart: "no"` prevents
a completed test from restarting. Prometheus is an external consumer of the
remote-write stream, not a declared k6 dependency, so it must be prepared first
when metrics retention is required.

### Normal Use

1. Review the target, traffic ceiling, stop conditions, credentials, and test
   script with the target owner. Never point a default smoke test at production.
2. Run repository checks from the project root:

   ```bash
   bash scripts/hardening/check-all-hardening.sh 09-tooling
   HYHOME_COMPOSE_PROFILES=testing bash scripts/validation/validate-docker-compose.sh
   ```

3. For an approved live test, start only the job and watch its logs:

   ```bash
   docker compose --profile testing up --no-deps --abort-on-container-exit k6
   docker compose --profile testing logs --tail=200 k6
   ```

4. Correlate the summary and exit code with target-side latency, errors, and
   saturation. A rendered service or started container is not target readiness.

### State and Upgrade

The service itself is disposable. Back up version-controlled scenarios and any
retained result/evidence store; Prometheus owns remote-write retention. Before an
image upgrade, review k6 release notes, run a low-load canary against a disposable
target, and confirm output names used by the dashboard. Roll back the image pin
and scenario together if result semantics change.

## Common Checks

- `bash scripts/hardening/check-all-hardening.sh 09-tooling`
- `HYHOME_COMPOSE_PROFILES=testing bash scripts/validation/validate-docker-compose.sh`
- For an approved run, confirm the `k6` exit code, sanitized summary, receiving
  Prometheus evidence, and target-side recovery signals.
