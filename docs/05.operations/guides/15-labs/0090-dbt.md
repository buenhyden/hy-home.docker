# dbt Usage Guide

## Purpose

### Outcome

dbt는 root Compose에서 분리된 독립 LAB `labs/dbt/docker-compose.yml`의 command-line 변환 작업이며 LAB
profile `lab-dbt`로 선택된다(SPEC-0262). web UI가 없으므로 route나 OIDC
client가 없고 필요하지도 않다. root `analytics-engineering` profile은 이제 HOME dev-pg 기반만
선택하고 dbt를 선택하지 않는다.

dbt 변환 작업을 실행하는 분석 엔지니어와 운영자를 위한 문서다. 명령의 부작용과 권한 경계를 이해하고 안전하게 실행·점검하는 것이 목표다.

## Prerequisites

### Environment

#### Current implementation

- [dbt LAB Compose](../../../../labs/dbt/docker-compose.yml)는 feature
  SQL을 실행하는 `dbt-db-provision`과 `dbt` job을 `hy-home-lab-dbt` project의 `lab_dbt_net`에
  정의한다. 두 서비스는 `hy-home.tier: lab`, `traefik.enable: 'false'` label을 가진다.
- LAB은 HOME network에 합류하지 않는다. HOME dev-pg는 필수 입력 `LAB_DBT_DB_HOST`/
  `LAB_DBT_DB_PORT`([`labs/.env.example`](../../../../labs/.env.example))로만 지정하며, 비어
  있으면 렌더링이 거부된다. HOME은 기본적으로 database port를 LAB network에 게시하지 않으므로
  소유자가 도달 가능한 endpoint를 승인하기 전까지 이 LAB은 렌더링 전용이다(SPEC-0262 Task의
  미결정 항목, 별도 승인). `platform_dev` fixture는 HOME `dev-platform-provision`이 먼저
  만들어야 한다.
- secret은 LAB 전용이다. 이름은 `lab_dbt_<purpose>`이고 파일은
  `${LAB_SECRET_DIR:-../../secrets/labs}/dbt/` 아래에 있으며 원래 `/run/secrets/<name>` target에
  mount되고 group은 `LAB_SECRETS_GID`다. 값은 복사되지 않았으므로 운영자가 dev-pg 관리자와 dbt
  비밀번호의 LAB 사본을 별도 승인 아래 준비해야 한다(미결정 항목).
- role `DBT_DB_USER`는 `platform_dev`에
  연결한다. application owner가 나중에 생성한 table을 포함해 `app` source schema를
  읽을 수 있고 `DBT_SCHEMA`를 소유한다. schema를 생성하거나 source schema에
  쓸 수는 없다.
- project와 profile은 read-only mount이다. `target/`, `logs/`, `packages/`는
  job의 `/tmp` tmpfs에 있으며 container와 함께 사라진다.
- project는 connection과 target-schema write access를 증명하는 smoke view인
  `hyhome_dbt_connectivity`만 제공한다. 비즈니스 model은 아직 정의되지
  않았다.

### Permissions

secret은 LAB 전용 `lab_dbt_<purpose>`이며 dev-pg 관리자와 dbt 비밀번호의 LAB 사본은 별도 승인 아래 준비한다. dbt에는 `CREATE` 권한을 의도적으로 부여하지 않았다.

## Procedure

### Actions

#### Identity-specific behavior

실제 실행 입력은 mounted profile·project와 secret wrapper이며, dbt core·adapter·Python 버전은 [Dockerfile](../../../../labs/dbt/Dockerfile)이 소유한다. `dbt-db-provision`은 공유 runner로 role, CONNECT, source SELECT, target-schema 권한을 변경한다. 입력 오류와 timeout은 종료 코드 `64`, SQL 오류는 `3`이며 다른 shell 오류와 구분한다. `ON_ERROR_STOP`도 이미 커밋된 DDL을 되돌리지 않는다. `debug`나 기본 smoke view 성공을 모든 model 실행 성공으로 확대하지 않는다. `test`와 `compile`도 앞으로 추가될 custom macro·hook까지 읽기 전용이라고 보장하지 않으므로 model/code review가 필요하다.

| 정확한 식별자 | 목적·상태·기동 차이 | 준비 상태 판단의 한계 | 구현 소유자 |
| --- | --- | --- | --- |
| `dbt` | one-shot CLI; debug 기본, model run/build는 DDL/DML | HTTP health 없음; 종료 코드와 읽기/검증 결과 확인 | [선택·의존·접속·입력·mount](../../../../labs/dbt/docker-compose.yml) |
| `dbt-db-provision` | target schema/source SELECT feature provisioning job | HTTP health 없음; 종료 코드와 변경된 대상의 실제 상태 확인 | [선택·의존·접속·입력·mount](../../../../labs/dbt/docker-compose.yml) |

선택 profile, version, port, 환경 입력, secret identifier와 mount의 정확한 값은 각 행의 구현이 소유한다. [공통 template](../../../../infra/common-optimizations.yml)의 resource·security 상속과 서비스 override를 함께 읽는다. 값의 2026-10-01 source snapshot과 official version/build 검토는 W4 Task에 보존했다. 반복 OOM, disk/WAL/checkpoint 증가와 metrics 누락은 capacity 검토 trigger이며 health는 사용자 기능이나 복원을 증명하지 않는다.

#### Commands and side effects

아래 진단은 승인된 dev-pg endpoint가 healthy이고 HOME base provisioning과 LAB feature provisioning이 이미 완료된 승인 환경에서만 수행한다. 미완료라면 중단하고 [dbt runbook](../../runbooks/15-labs/0090-dbt.md#actions)의 named provisioning 승인을 따른다. `--no-deps`는 `dbt-db-provision`의 암묵 실행을 막으며 최초 provisioning을 대신하지 않는다. HOME `dev-platform-provision`은 LAB의 dependency가 아니므로 HOME에서 따로 실행한다. 표는 client/model의 효과를 설명한다. `run`/`build` 및 사용자 hook·macro의 쓰기 효과는 별도로 승인해야 한다.

| 명령 | Database에 미치는 영향 | 입증하는 내용 |
| --- | --- | --- |
| `dbt --version` | 없음 | image가 시작함; database에 대해서는 아무것도 증명하지 않음 |
| `dbt debug`(기본값) | connection을 염 | profile과 credential이 동작함 |
| `dbt compile` | Read-only introspection | SQL이 catalog에 대해 render됨 |
| `dbt run` / `dbt build` | `DBT_SCHEMA`에 relation을 생성/교체함; `build`는 test도 실행 | 선택된 model이 materialize됨 |
| `dbt run --full-refresh` | incremental model을 drop하고 재구축 | 재구축; 오래 걸릴 수 있고 incremental 상태를 잃음 |
| `dbt test` | Read query | data test 통과 |

`docker compose --env-file labs/.env -f labs/dbt/docker-compose.yml --profile lab-dbt run --rm --no-deps dbt <command>`로
command를 실행한다. 렌더링만 하는 `config`를 제외한 실행은
`python3 scripts/operations/lab.py check|up|down dbt`의 목적·lease·충돌·예산 규칙을 따른다. `dbt test --store-failures`는 audit schema에 대한
`CREATE` 권한이 필요하지만 이 권한은 의도적으로 부여하지 않았다.

### Exceptions

이 가이드는 Troubleshooting에 적은 내용 외의 예외를 따로 기록하지 않는다.
