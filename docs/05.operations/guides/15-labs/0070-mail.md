# Stalwart Mail Server Guide

## Overview

이 가이드는 독립 LAB `labs/stalwart/docker-compose.yml`(project `hy-home-lab-stalwart`)의 메일 서버 Stalwart 구성, 네트워크 경계, 일반 사용 방법을 설명한다. LAB profile `mail-server`에서만 선택되고 root Compose에는 포함되지 않으며(SPEC-0262) HOME 개발용 메일 캡처인 Mailpit과는 구분된다.

## Scope

### Audience and Goal

대상 독자는 내부 메일 서버를 켜거나 변경하는 운영자다. 목표는 서버가 실제로 노출하는 listener, 네트워크, 인증 경계를 이해하고 일반 사용과 점검 방법을 찾는 것이다. 기동, 복구, 업그레이드 절차는 [RUN-0070](../../runbooks/15-labs/0070-mail.md)이 소유한다.

## Concepts

### 목적과 분류

Stalwart는 HOME 의존성이 없는 자체 완결 LAB 메일 서버이다. `mail-server`에서만 선택되며 HOME
`mail_net`에 남은 Mailpit 캡처와는 구분된다. LAB은 HOME network에 합류하지 않으므로 어떤 HOME
container도 Stalwart에 메일을 제출할 수 없다(Opsflow notifier는 Mailpit을 사용한다). SMTP 25/587은
LAB network `lab_stalwart_net`에만 있고, 웹 admin과 JMAP(8080)은 gateway route나 SSO 없이
`${LAB_HOST_BIND_IP:-127.0.0.1}:${LAB_STALWART_HOST_PORT:-18093}`에만 게시된다. 릴레이는 전혀 하지
않는다. 설정된 도메인 외부의 수신자는 거부된다.

## Usage

### 현재 구현

- [Stalwart Compose](../../../../labs/stalwart/docker-compose.yml)는
  읽기 전용 root, `cap_drop:
  ALL`과 `NET_BIND_SERVICE`(바이너리 파일 capability)만으로 자체 사용자(UID 2000)로
  이미지를 실행한다. host에는 8080만 LAB bind 주소로 게시한다.
- `config/config.json`은 datastore만 지정한다(`/var/lib/stalwart`의 RocksDB,
  `${LAB_DATA_DIR}/stalwart/data`에서 바인드됨). 나머지는 모두 datastore에 저장된다.
  이전 `${DEFAULT_COMMUNICATION_DIR}/stalwart/data`의 데이터는 옮기지 않았으며, 옮기려면
  별도 승인 아래 수동으로 이전한다.
- `stalwart-config`는 pin된 `stalwart-cli`로
  [config/plan.ndjson](../../../../labs/stalwart/config/plan.ndjson)을
  적용한다: 도메인 `${DEFAULT_URL}`(LAB 입력 `LAB_STALWART_DEFAULT_URL`), 호스트 이름 `mail.${DEFAULT_URL}`, 정확히
  4개의 listener(SMTP 25, submission 587, IMAPS 993, HTTP 8080),
  `allowRelaying = false`. listener 집합 전체를 reconcile하므로 plan에 없는 listener를
  삭제할 수 있다. 일치하는 객체는 patch되며 순차 적용 중 일부만 반영될 수 있다.
  재실행은 진단이나 자동 롤백이 아니다. listener 변경은 다음 서버 재시작 때 적용된다.
- `stalwart_password`(LAB-036)는 서버와 job 프로세스 내부에서만 복구용 admin이
  되며, Compose 파일에는 credential이 없다. 이 secret은 LAB 전용(`lab_stalwart_*`, 파일은
  `${LAB_SECRET_DIR:-../../secrets/labs}/stalwart/password.txt`)으로 원래 `/run/secrets/` 대상 경로에 mount되며 group은
  `LAB_SECRETS_GID`다. 소유자가 HOME 파일을 이 LAB 사본으로 옮겼고, 옛 COMM-006은 LAB-036의
  퇴역 alias다.
- 587/993의 TLS는 Certificate 객체가 설정되기 전까지 Stalwart의 기본 인증서를
  사용한다. `lab_stalwart_net`의 클라이언트는 이를 명시적으로 신뢰해야 한다.
- healthcheck는 8080의 `/healthz/live`를 읽으며, 이는 배달 준비 상태가 아니라
  프로세스 liveness이다.
- 이 이미지는 업스트림에서 AGPL-3.0 또는 Stalwart Enterprise License로 이중
  라이선스된다. 추적되는 라이선스 키가 없으므로 Enterprise 기능은 증명되지 않는다.
  이에 의존하지 않는다.

### 소스 검토의 한계

여기서 설명한 네트워크는 선언상 연결 가능한 경로다. 실제 peer 연결·인터넷 공개·
사용자 인증·복구 성공을 이번 문서 작업에서 시험하지 않았다. 현재 선언의 제한을
해소하는 구현 변경은 별도 승인·보안 검토·검증이 필요하다.

### Runbook Handoff

listener 실패, 데이터 복구, 업그레이드에는 [runbook](../../runbooks/15-labs/0070-mail.md)을
사용한다. 최초 기동 순서는 런북의 `승인된 최초 기동`, 백업과 업그레이드는 `Backup and isolated restore`와 `Upgrade` 절차를 따른다. 데이터와 권한 경계는 [정책](../../policies/15-labs/0070-mail.md)을 유지한다.
