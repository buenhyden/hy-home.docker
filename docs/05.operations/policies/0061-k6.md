# k6 Operations Policy

## Overview

k6는 명시적으로 선택되는 `testing` job이다. live run은 다른 system으로 가는
traffic을 생성하므로 target-owner 승인과 기록된 한도가 필요하다.

## Policy Scope

이 정책은 `k6` service, read-only scenario mount, remote-write output,
image upgrade, 보관된 run evidence를 다룬다.

## Controls

- `testing`만 선택한다; `tooling`은 k6를 시작해서는 안 된다.
- live command에서 `k6` service를 명시한다. 하나의 test를 위한 shortcut으로
  넓은 profile을 시작하지 않는다.
- 대상·스크립트 revision·test ID·트래픽 모델·최대 시간·중단 조건·소유자 승인과
  결과를 기록한다. credential과 response body는
  script, log, evidence에 남기지 않는다.
- 승인된 target SLI threshold, 예상치 못한 endpoint, authorization
  failure, 합의된 test boundary를 벗어난 saturation이 발생하면 즉시
  중지한다.
- `restart: "no"`, read-only script, 게시되지 않은 port, 명시적인
  remote-write destination을 유지한다. metric retention이 필요한 경우
  run 전에 Prometheus availability를 확인한다.
- 시나리오는 Git으로 관리해야 한다. 현재 입력은 호스트 bind이므로 관리 여부를
  별도로 확인하고, 미추적 파일은 승인된 검토본·해시·복구본을 먼저 확보한다.
  시계열 보존은 metrics backend가 소유하며 작업 컨테이너는 폐기할 수 있다.
- 불변 이미지 식별자·릴리스 검토·폐기 가능한 대상의 canary·rollback 근거를
  확보하고 업그레이드한다. pull이 성공했다고 해서 compatibility를
  추론하지 않는다.

## Verification

live run 전에 [Runbook](../runbooks/0061-k6.md)에 따라 hardening과 Compose validation을 통과해야 한다.

Runtime evidence는 승인된 test에만 유효하며, job exit code와 target-side
signal을 포함해야 한다.

## Exceptions

검토된 target, traffic model, duration, stop condition, credential
boundary에서 벗어나는 모든 편차에는 expiry와 rollback을 갖춘 target-owner 승인이
필요하다.

## Review Cadence

target이나 scenario가 변경될 때마다, 그리고 k6 image, remote-write
contract, receiving dashboard가 변경될 때마다 검토한다.
