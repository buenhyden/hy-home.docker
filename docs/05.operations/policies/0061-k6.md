# k6 Operations Policy

## Overview

### Overview

k6는 명시적으로 선택되는 `testing` job이다. root Compose service는 `version`만
실행하는 inventory/render 경계이고, 트래픽 실행 인터페이스는 승인된 `quality_run.py`
isolated executor만 가질 수 있다. executor는 승인된 exact-path guard config 없이는
container를 시작하지 않으며, live target traffic 승인은 `BLOCKED`다. 어느 실행도 target-owner 승인과
기록된 한도 없이 수행하지 않는다.

## Scope

### Policy Scope

이 정책은 root `k6` inventory service, isolated executor, read-only scenario
snapshot, result artifact, remote-write declaration, image upgrade와 보관된 run
evidence를 다룬다.

## Rules

### Controls

- `testing`은 root inventory/render에만 사용한다; `tooling`은 k6를 실행해서는 안
  되며 root service command를 덮어써 부하를 생성해서는 안 된다.
- 실제 실행은 versioned manifest를 validate한 isolated executor만 사용한다. 전용
  internal network, manifest run identity와 subnet, 단일 labeled WireMock peer,
  private target origin, read-only scenario snapshot, 빈 attempt directory가 모두
  검증되지 않으면 fail closed한다.
- 대상·scenario revision·run/attempt identity·트래픽 모델·최대 시간·중단 조건·소유자
  승인과 final state를 기록한다. credential, raw stdout/stderr, request/response body,
  cookie, Authorization, URL query는 script, log, evidence에 남기지 않는다.
- 승인된 target SLI threshold, 예상치 못한 endpoint, authorization
  failure, 합의된 test boundary를 벗어난 saturation이 발생하면 즉시
  중지한다.
- `restart: "no"`, root service의 read-only script mount, 게시되지 않은 port와
  remote-write declaration을 유지한다. declaration은 delivery·retention 증거가
  아니며 isolated executor는 remote write를 사용하지 않는다. live metric은 manifest
  v2 `telemetry.mode=otlp`와 run별 `metrics-ingress` relay로만 HOME Alloy 인증 수신기에
  보내고, k6 container는 token을 받지 않는다.
- 시나리오는 Git으로 관리해야 한다. 현재 입력은 호스트 bind이므로 관리 여부를
  별도로 확인하고, 미추적 파일은 승인된 검토본·해시·복구본을 먼저 확보한다.
  시계열 보존은 metrics backend가 소유하며 작업 컨테이너는 폐기할 수 있다.
- 불변 이미지 식별자·릴리스 검토·폐기 가능한 대상의 canary·rollback 근거를
  확보하고 업그레이드한다. pull이 성공했다고 해서 compatibility를
  추론하지 않는다.

### Verification

live run 전에 [Runbook](../runbooks/0061-k6.md)에 따라 hardening과 Compose validation을 통과해야 한다.

Runtime evidence는 승인된 isolated test에만 유효하며 sanitized final state, exit
metadata, target-side signal과 exact cleanup receipt를 포함해야 한다. 현재 executor는
container를 만들지 않아 cleanup receipt와 target-side signal도 `NOT_RUN`이다. root
Compose render, `k6 version`, dashboard panel 또는 remote-write URL은 runtime evidence가
아니다.

### Review Cadence

target이나 scenario가 변경될 때마다, 그리고 k6 image, OTLP metric
contract, metrics ingress, receiving dashboard가 변경될 때마다 검토한다.

## Exceptions

### Exceptions

검토된 target, traffic model, duration, stop condition, credential
boundary에서 벗어나는 모든 편차에는 expiry와 rollback을 갖춘 target-owner 승인이
필요하다.
