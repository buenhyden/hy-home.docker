# dbt Operations Policy

## Overview

dbt는 application 데이터베이스에 파생된 relation을 기록한다. 그 권한은 source 읽기와
target schema 소유로 제한해야 한다.

## Policy Scope

Provisioning, grant, 부작용이 있는 명령어, credential, 제거.

## Controls

- `analytics-engineering`을 통해서만 선택한다. dbt를 장기 실행 서비스로 만들거나 그런
  서비스용 OIDC web front end를 추가하지 않는다.
- dbt grant는 `mng-pg-init`이 아니라 feature provisioning SQL에 있다. role은
  `NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION`이며 절대 source schema를
  소유하지 않는다. target schema는 source schema와 달라야 한다.
- `run`, `build`, `--full-refresh`는 검토된 model selection이 필요하다. `--version`이나
  `debug` 출력은 절대 model run으로 기록하지 않는다.
- 프로젝트와 profile은 read-only로 유지한다. 생성된 artifact는 tmpfs에 남는다.


### Accountable lifecycle boundary

적용 identity: `dbt`, `dbt-db-provision`. 문서의 정적 검증과 runtime 운영 승인을 분리한다. @buenhyden이 named consumer·target·중단 영향·보존 기간과 예외를 소유한다. service image/profile/port/secret/mount, DDL·init, capacity 또는 backup 범위 변경 시 이 Policy와 linked Guide/Runbook을 함께 검토한다. engine secret/certificate는 이 subject의 credential 계약을, 앱 인증 연동은 적용되는 [POL-0079](0079-application-auth-integration.md)를, source 반영·재기동은 [POL-0006](0006-infrastructure-optimization-governance.md#source-and-lifecycle-boundary), 보존·삭제는 [POL-0021](0021-backup-and-restore.md)의 적용 통제를 따른다. exporter와 stateless job 자체에는 database restore가 없지만 설정·credential와 그 작업이 변경하는 upstream state는 제외되지 않는다. 소유 artifact·복구 지점·expiry가 불명확하면 삭제/재생성을 중단한다. 기존 Exceptions 외의 새 예외는 승인된 것으로 간주하지 않는다.

## Exceptions

없음. grant를 넓히려면(예: 데이터베이스에 대한 `CREATE`) 이유를 명시한 검토된
변경이 필요하다.

## Verification

정적 렌더링과 provisioning 테스트. 일회성 리허설로 source 읽기, target 쓰기,
source schema 거부를 증명한다.

## Review Cadence

dbt나 adapter 업그레이드, 신규 source, grant 변경 시 검토한다.
