# Stalwart Mail Operations Policy

## Purpose

### Objective

Stalwart는 독립 LAB `labs/stalwart/docker-compose.yml`의 메일 서비스다. 프로토콜 리스너, relay 규칙, 메일박스 데이터는 관리 UI 경로 이상의 통제가 필요하다. 이 정책은 그 통제를 정의한다.

### Authority

- [가이드](../../guides/15-labs/0070-mail.md) (`GDE-0070`)
- [런북](../../runbooks/15-labs/0070-mail.md) (`RUN-0070`)
- [Communication 아키텍처](../../../02.architecture/descriptions/0010-communication-architecture.md)
- SPEC-0262 Analytics labs migration(LAB 이전)
- [Stalwart Compose 소스](../../../../labs/stalwart/docker-compose.yml) 및 [파생 버전 projection](../../../../infra/tech-stack.versions.json)

## Scope

### Applies To

활성화, DNS/TLS, 프로토콜 인증/relay, 메일박스/설정 데이터, 보존, 백업/복구,
라이선스/업그레이드, 제거.

### Exclusions

Mailpit 개발 캡처를 Stalwart로 대체하는 것과 root나 HOME에 포함하는 것은 새로운 승인된 요구사항 없이는 이 정책의 대상이 아니다.

## Rules

### Requirements

- **Activation:** LAB profile `mail-server`만 `scripts/operations/lab.py` lease로 사용한다.
  Mailpit 개발 캡처를 Stalwart로 대체하거나 새로운 승인된 요구사항 없이 root나 HOME에 포함하지 않는다.
- **Network/auth:** LAB은 HOME network에 합류하지 않는다. SMTP와 IMAP은 LAB network
  `lab_stalwart_net`에 한정하고, host에는 admin·JMAP 8080만 `${LAB_HOST_BIND_IP:-127.0.0.1}` bind의
  `LAB_STALWART_HOST_PORT`로 게시한다. loopback 밖 bind나 SMTP host 게시는 별도 보안·구현 검토를
  거쳐야 하며 문서만으로 경계를 넓히지 않는다. 추적 중인 plan이 리스너 집합을 소유하며(조정됨),
  `allowRelaying = false`를 유지한다. 리스너나 relay 변경은 UI 편집이 아니라
  검토된 plan 변경이다. Gateway route와 SSO는 없다. `lab_stalwart_net`의
  구성원과 게시된 port에 도달하는 host 사용자는 관리 API와 JMAP(8080)에, network 구성원은
  IMAPS(993)에도 직접 도달할 수 있으므로 LAB network 멤버십과 port bind가 신뢰 경계이며, 구성원 추가는 리스너 변경과 마찬가지로
  검토된 변경이다.
- **Fallback admin:** `stalwart_password`에서 나온 복구 관리자는 매 시작마다
  활성화되어 있으며, 관리 UI에 대한 이후의 네이티브 OIDC를 포함해 어떤
  디렉터리나 OIDC 로그인도 우회한다. 회전은 [런북](../../runbooks/15-labs/0070-mail.md)의 재생성·이전 자격 증명 거부 검증을 따른다.
  helper는 같은 secret으로 로그인하지만 회전을 확인하려고 plan을 자동 재적용하지
  않는다. 그 계정을 대화형으로 쓰면 에스컬레이션이다.
- **Admin UI login:** gateway SSO가 없으므로 Stalwart 관리자 로그인만 적용된다
  (2026-09-24 소유자 결정의 SSO 단계는 SPEC-0262 LAB 이전으로 사라졌다). Stalwart의 OIDC 디렉터리는 모든 계정의
  비밀번호 백엔드를 대체해 IMAP과 SMTP 클라이언트에 App Password가
  필요해지므로 채택하지 않는다.
- **Secrets/data:** 관리자, 메일박스, DKIM, TLS, 백엔드 자격 증명을
  소스/로그에 두지 않는다. 복구 관리자는 `stalwart_password` 시크릿
  파일에서만 나온다. 메일박스 콘텐츠와 메타데이터를 민감한 개인 데이터로
  취급한다.
- **Retention:** 구성된 백엔드와 보존/삭제(expunge) 일정을 기록한다. 적용
  가능한 라이선스와 설정이 검증되지 않는 한 Enterprise 삭제 항목 복구를
  주장하지 않는다.
- **Backup/recovery:** 설정 객체, 구성된 모든 데이터/blob/검색 백엔드,
  인증서/키 보관, DNS/DKIM 상태를 캡처한다. 아웃바운드 전송을 차단한 상태로
  복구하고 합성 검증을 수행한다.
- **Resources:** 읽기 전용 infra-medium 기준선을 변경하기 전에 queue, 저장소
  증가, 인덱싱, 프로토콜 부하를 측정한다.
- **Upgrade/license:** 선택한 upstream 라이선스와 릴리스/저장소 마이그레이션을
  검증한다. 승격 전에 백업 복구와 리스너를 테스트한다.
- **Removal:** 통제된 순서로 메일박스/설정을 내보내고 DNS/경로/키를
  폐기하며, bind 디렉터리 삭제는 별도로 승인한다.

### Enforcement

SMTP 포트 헬스는 부분적이다. 수용 기준은 인증된 제출, IMAP, TLS 인증서, DNS,
relay 거부, 합성 전송을 포함하며 복구를 주장하는 경우 복구도 포함한다.

## Exceptions

### Exception Conditions

오픈 relay를 생성하거나, 제한 없는 마이그레이션 없이 프로토콜 TLS를
약화하거나, 명시적인 처리 없이 메일박스 데이터를 폐기하는 예외는 없다.

### Approval and Review

활성화 전, 그리고 리스너, DNS, 백엔드, 보존, 이미지, 라이선스 변경 시
검토한다.
