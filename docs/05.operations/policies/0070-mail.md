# Stalwart Mail Operations Policy

## Overview

Stalwart는 OPTIONAL 내부 메일 서비스다. 프로토콜 리스너, relay 규칙, 메일박스
데이터는 관리 UI 경로를 넘어서는 통제를 필요로 한다.

## Policy Scope

활성화, DNS/TLS, 프로토콜 인증/relay, 메일박스/설정 데이터, 보존, 백업/복구,
라이선스/업그레이드, 제거.

## Controls

- **Activation:** `mail-server`만 사용한다. Mailpit 개발 캡처를 Stalwart로
  대체하거나 새로운 승인된 요구사항 없이 HOME에 포함하지 않는다.
- **Network/auth:** 호스트 포트가 없다. SMTP와 IMAP은 `mail_net`에서만
  도달 가능하다. 추적 중인 plan이 리스너 집합을 소유하며(조정됨),
  `allowRelaying = false`를 유지한다. 리스너나 relay 변경은 UI 편집이 아니라
  검토된 plan 변경이다. Gateway SSO는 라우팅된 웹 UI만 다룬다. `mail_net`의
  구성원은 관리 API와 JMAP(8080), IMAPS(993)에 직접 도달할 수 있으므로
  `mail_net` 멤버십이 신뢰 경계이며, 구성원 추가는 리스너 변경과 마찬가지로
  검토된 변경이다.
- **Fallback admin:** `stalwart_password`에서 나온 복구 관리자는 매 시작마다
  활성화되어 있으며, 관리 UI에 대한 이후의 네이티브 OIDC를 포함해 어떤
  디렉터리나 OIDC 로그인도 우회한다. 시크릿 파일을 교체하고 `stalwart`를
  재시작한 뒤 `stalwart-config`를 다시 실행하여 회전한다(해당 job은 같은 값으로
  로그인한다). 그 계정을 대화형으로 사용하는 것은 에스컬레이션이다.
- **Admin UI login:** gateway SSO 다음 Stalwart 관리자 로그인 순서를 따른다
  (소유자 결정, 2026-09-24). Stalwart의 OIDC 디렉터리는 모든 계정에 대해
  비밀번호 백엔드를 대체하게 되어 IMAP과 SMTP 클라이언트가 App Password를
  필요로 하게 되므로, 채택하지 않는다.
- **Secrets/data:** 관리자, 메일박스, DKIM, TLS, 백엔드 자격 증명을
  소스/로그에 두지 않는다. 복구 관리자는 오직 `stalwart_password` 시크릿
  파일에서만 나온다. 메일박스 콘텐츠와 메타데이터를 민감한 개인 데이터로
  취급한다.
- **Retention:** 구성된 백엔드와 보존/삭제(expunge) 일정을 기록한다. 적용
  가능한 라이선스와 설정이 검증되지 않는 한 Enterprise 삭제 항목 복구를
  주장하지 않는다.
- **Backup/recovery:** 설정 객체, 구성된 모든 데이터/blob/검색 백엔드,
  인증서/키 보관, DNS/DKIM 상태를 캡처한다. 아웃바운드 전송을 차단한 상태로
  복구하고 합성 검증을 수행한다.
- **Resources:** 읽기 전용 infra-medium 기준선을 변경하기 전에 queue, 저장소
  증가, 인덱싱, 프로토콜 부하를 측정한다.
- **Upgrade/license:** 선택한 upstream 라이선스와 릴리스/저장소 마이그레이션을
  검증한다. 승격 전에 백업 복구와 리스너를 테스트한다.
- **Removal:** 통제된 순서로 메일박스/설정을 내보내고 DNS/경로/키를
  폐기하며, bind 디렉터리 삭제는 별도로 승인한다.

## Exceptions

오픈 relay를 생성하거나, 제한 없는 마이그레이션 없이 프로토콜 TLS를
약화시키거나, 명시적인 처리 없이 메일박스 데이터를 폐기하는 예외는 없다.

## Verification

SMTP 포트 헬스는 부분적이다. 수용 기준은 인증된 제출, IMAP, TLS 인증서, DNS,
relay 거부, 합성 전송, 그리고 주장된 경우의 복구를 포함한다.

## Review Cadence

활성화 전, 그리고 리스너, DNS, 백엔드, 보존, 이미지, 또는 라이선스 변경 시
검토한다.
