# Entrypoint README Registration Specification

## Overview

Twelve folders sit at the repository entrypoint layer. Six carried a README the
Stage 99 registry recognized; six did not, and an unrecognized README is
unenforced prose. This package puts every one of them on the registry form
mapped to its path, and makes the mapping the thing that decides which form
applies.

## Boundaries and Inputs

- In scope: `_workspace`, `.agents`, `.claude`, `.codex`, `.github`, `evals`,
  `examples`, `infra`, `projects`, `scripts`, `secrets`, `tests`.
- In scope: the registry profiles, path allowlist, and section gate that decide
  whether a README form is enforced.
- Out of scope: the body content of already-conforming READMEs beyond stale
  references discovered while reading them.

## Behavior Contract

1. Every entrypoint folder has one README classified into a registry profile.
2. A README form is identified by its registered profile, not by its filename.
3. Declared template links name the template the registry actually maps.
4. `.github` keeps one surface map, named `repository-surface.md`.
5. `evals/` is the agent evaluation harness root and is governed like
   `scripts/`.

## Technical Approach

`repository-readme` gains `.github/repository-surface.md`, `_workspace/README.md`,
`evals/README.md`, and `examples/README.md`. `runtime-governance-readme` gains
`.claude/README.md` and `.codex/README.md`, generated by the provider surface
renderer from declared projections rather than hand-written. `registry.py`
extends `_NON_DOCS_FILES` so registry authority reaches those exact paths and no
others.

The README section gate keys on profile type instead of filename, so a README
form renamed for an external reason stays enforced.

`MANIFEST_ROOTS` replaces the two independent `scripts/` literals in the script
manifest checker, so declaration and coverage widen together and cannot drift.

## Interfaces and Data

- `docs/99.templates/registry.json`: profile membership and template mapping.
- `docs/00.agent-governance/providers/registry.yaml`: runtime README projections.
- `.github/workflow-contract.yml`: changed-path suite routing for `evals/` and
  `_workspace/`.
- `scripts/manifest.yaml`: rows for the relocated harness and its contract.

## Failure Modes and Guardrails

- A README form renamed away from `README.md` silently loses section checks.
  Guarded by the profile-keyed gate and a mutation test.
- A new `evals/` executable ships unregistered. Guarded by `MANIFEST_ROOTS`
  driving coverage as well as declaration; verified by mutation.
- A validator moves out of its routed prefix and stops gating itself. Guarded by
  `target_surface_delta_contract`, which raised exactly this during the move.

## Acceptance Contract

1. All twelve folders classify into a registry profile and satisfy its declared
   sections.
2. `run-ci-gate.py --profile full` exits `0`.
3. The relocated harness reports `fixtures_check=pass` and
   `regressions_check=pass`.
4. The authoring matrix and the registry agree on family and kind in both
   directions.
